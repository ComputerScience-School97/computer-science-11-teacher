## ⚠ Прочитай до уроку: чому день побудований у два рівні

React потребує **збірки**. Варіанти без збірки вимагають завантаження бібліотеки з інтернету, і на шкільній мережі це ненадійно.

Тому день має **два рівні**, і перший обов'язковий для всіх:

| Рівень | Що робиться | Що потрібно |
|---|---|---|
| **Частини 1–5** | компонентний підхід і керування станом **на чистому JavaScript** | нічого |
| **Частина 6** | те саме в React через Vite | працюючий npm |

Це не поступка. Головне, що вимагає держпрограма — **«компонентний підхід»** — засвоюється саме в частинах 1–5. React додає синтаксис, але не додає ідеї. Учень, який зрозумів частини 1–5, розбереться з React за вечір; учень, який скопіював React-код, не зрозумівши моделі, не вміє нічого.

**Перевір до уроку:** `npm create vite@latest test-app -- --template react` у порожній папці. Якщо проходить — частина 6 доступна. Якщо ні — скажи класу на початку, що працюємо до частини 5, і зіркові завдання беруться з іншого списку.

Ні. Це третій раз за курс:

| Де | Що дублювалось | Ліки |
|---|---|---|
| день 3 | дані в таблиці | окремі таблиці |
| день 14 | код | функція |
| день 20 | оформлення | CSS-файл |

> **Компонент** — самостійна частина інтерфейсу, описана один раз
> і використана багато.

Це та сама ідея, що функція. Тільно функція повертає **розмітку**.

### 10–25 хв. Компонент і пропси 🗣

Пиши на проекторі, спираючись на їхній код дня 23.

Так виглядає їхня `renderClubs` зараз:

```javascript
function renderClubs(list) {
    let html = "";
    for (const club of list) {
        html += `
            <article class="club">
                <h3>${club.name}</h3>
                <p>Кабінет ${club.room}, ${club.weekday}</p>
                ...
            </article>
        `;
    }
    container.innerHTML = html;
}
```

Питання класу: **що тут робить одна функція?** Дві речі: описує вигляд однієї картки й керує списком. Це порушує правило дня 14 — «одна функція, одна задача».

Розділяємо:

```javascript
function ClubCard(club) {
    const percent = Math.round(club.enrolled / club.max * 100);
    return `
        <article class="club">
            <h3>${club.name}</h3>
            <p>Кабінет ${club.room}, ${club.weekday}</p>
            <p>Записано ${club.enrolled} з ${club.max}</p>
            <div class="progress">
                <div class="progress-fill" style="width: ${percent}%"></div>
            </div>
        </article>
    `;
}

function ClubList(clubs) {
    if (clubs.length === 0) {
        return "<p>Гуртків не знайдено.</p>";
    }
    return clubs.map(ClubCard).join("");
}
```

Тези, які варто назвати:

1. **Компонент — це функція, яка повертає розмітку.** Нічого більше.
2. **Пропси — це параметри цієї функції.** `club` — і є проп.
3. **Компонент нічого не знає про сторінку.** Він не звертається до `document`, не вставляє себе кудись. Він просто повертає рядок.
4. **Назви компонентів пишуть з великої літери.** Домовленість, за якою їх видно в коді.

⚠ Третя теза найважливіша. Це те саме правило, що в дні 14: **повертай, а не виводь**. Компонент, який сам себе вставляє в сторінку, не можна перевикористати.

### 25–38 хв. Стан і декларативність 🗣

Головна частина дня.

Поверни до зіркового завдання дня 23, де вони зводили пошук і фільтр разом:

```javascript
let currentDay = "";
let currentSearch = "";
```

> **Стан** — дані, від яких залежить те, що видно на екрані.

Тепер зберемо стан в одне місце:

```javascript
const state = {
    clubs: [],
    search: "",
    day: ""
};
```

І одна функція, яка малює **всю** сторінку зі стану:

```javascript
function render() {
    let visible = state.clubs;

    if (state.day) {
        visible = visible.filter(c => c.weekday === state.day);
    }
    if (state.search) {
        visible = visible.filter(c =>
            c.name.toLowerCase().includes(state.search.toLowerCase()));
    }

    container.innerHTML = ClubList(visible);
    updateFilterButtons();
}
```

Тепер обробники подій **не малюють нічого**. Вони змінюють стан і викликають `render()`:

```javascript
searchInput.addEventListener("input", () => {
    state.search = searchInput.value;
    render();
});
```

⚠ Це і є головна ідея дня. Сформулюй її на дошці:

```
   ІМПЕРАТИВНО (як робили досі)        ДЕКЛАРАТИВНО (як робимо тепер)

   натиснули кнопку                    натиснули кнопку
        ↓                                   ↓
   знайти елементи                      змінити стан
        ↓                                   ↓
   приховати одні                       перемалювати все зі стану
   показати інші
   зняти клас у трьох
   поставити клас в одному
```

> Замість «як змінити те, що на екрані» ми описуємо «як має виглядати екран
> при такому стані». Далі одна функція робить це щоразу однаково.

Питання класу: **чому це надійніше?**

Приклад із дня 23 відповідає сам: коли фільтрували приховуванням карток, список «тав», бо забували показати назад. З `render()` зі стану така помилка неможлива — кожен раз малюється все з нуля.

І фраза, яка веде до React:

> React — це бібліотека, побудована **рівно на цій ідеї**. Ви щойно
> написали React вручну. Далі — просто інший синтаксис.

### 38–45 хв. Що додає React 🗣

Коротко, без коду. Три речі:

**1. JSX** — розмітка пишеться прямо в коді, як теги, а не як рядок:

```jsx
function ClubCard({ club }) {
    return (
        <article className="club">
            <h3>{club.name}</h3>
        </article>
    );
}
```

⚠ Назви `className` замість `class` — бо `class` уже зайняте в JavaScript.

**2. `useState`** — стан, при зміні якого перемалювання відбувається **саме**:

```jsx
const [search, setSearch] = useState("");
```

Тобі більше не потрібно викликати `render()` руками.

**3. Перемалювання тільно того, що змінилось.** Їхня `render()` перебудовує весь список щоразу. React порівнює, що змінилось, і чіпає лише потрібне. На десяти гуртках різниці немає, на десяти тисячах — величезна.

Скажи чесно: **React потребує збірки**, тому в класі він може не запуститись. Якщо мережа дозволить — зробите частину 6. Якщо ні — ідея вже засвоєна, а синтаксис вивчається за вечір.

### На що дивитись, обходячи клас

1. **Компонент, який сам себе вставляє.** `container.innerHTML = ...` усередині `ClubCard`. Головна помилка дня. Питання, яке допомагає: «а якщо цю картку треба показати у двох місцях?»
2. **Стан у кількох місцях.** Половина в `state`, половина в окремих змінних. Вимагай одного об'єкта.
3. **Обробник, який малює сам.** Змінив стан **і** щось приховав. Так змішуються два підходи, і виходить гірше за обидва.
4. **`.map(ClubCard).join("")`.** Забутий `.join("")` дає коми між картками. Характерний симптом.

## Що піде не так

- **npm не працює.** Передбачено: частини 1–5 самодостатні.
- **`npm create vite` довго.** Кілька хвилин на завантаження. Якщо в класі 15 машин одночасно — мережа може не витримати. Порада: запускати хвилями.
- **React-проект не бачить сервер.** Vite піднімає свій сервер на іншому порту, і `fetch("/api/clubs")` піде не туди. Рішення в завданні є (`proxy` у `vite.config.js`), але це найскладніший технічний момент дня.
- **«Нащо це, якщо і так працювало».** Відповідь у дні 19 і в цьому уроці: дублювання розмітки. Покажи їхній власний `renderClubs` до й після — різниця видна.
- **Час.** Частини 1–5 займуть увесь урок у більшості. Це нормально. Частина 6 — для тих, хто швидкий.
- **Розчарування від React.** Хтось очікує «чарівництва» й отримує синтаксис. Скажи заздалегідь: ідея вже написана вами, React додає зручність, а не магію.
