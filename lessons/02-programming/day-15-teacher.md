### Проблема

SSMS підключається до SQL Server через **Windows-автентифікацію** — вона працює «сама», без пароля. Драйвер для Node так **не вміє**: стандартний драйвер `mssql` спілкується з сервером по мережевому протоколу, і йому потрібні логін та пароль.

Тому перед першим запитом з коду доведеться:

1. увімкнути на сервері **змішаний режим автентифікації** (Mixed Mode)
2. створити логін SQL Server із паролем
3. **перезапустити службу SQL Server** — це вимагає прав адміністратора

Крок 3 — точка ризику. Якщо в учнів немає прав адміністратора на машинах, він не пройде.

### Що зробити заздалегідь

**Перевір на одній машині весь ланцюжок** до уроку. П'ять хвилин, які вирішують, чи відбудеться день 15 як заплановано:

1. SSMS → права кнопка по сервері → **Properties** → **Security** → чи можна вибрати `SQL Server and Windows Authentication mode` і натиснути OK
2. Права кнопка по сервері → **Restart** → чи проходить без помилки прав
3. `npm install mssql` у порожній папці → чи не блокує мережа доступ до registry.npmjs.org

### Якщо крок 2 не проходить

Не ламай урок. Є **резервний план**, і він не гірший методично: замість бази програма читає дані з **JSON-файлу**, який учні експортують із SSMS.

Тоді структура дня змінюється так:

| | Основний план | Резервний план |
|---|---|---|
| Частина 2 | npm, `package.json` | те саме |
| Частина 3 | увімкнути SQL-автентифікацію | експорт даних із SSMS у JSON |
| Частина 4 | `.env` і секрети | те саме, але для шляху до файлу |
| Частина 5 | `SELECT` з коду через `mssql` | читання JSON через `fs` |
| Частина 6 | обробка результату | те саме |

Головна ідея дня — **дані приходять зовні, а не написані в коді** — зберігається повністю. У блоці 3 при роботі з API це знадобиться однаково.

Файл учня має обидва варіанти. **Скажи на початку уроку, за яким варіантом працює клас.**

## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–12 хв. Чужий код: npm 🗣

Постав питання: **як програма взагалі спілкується з SQL Server?**

Розверни: SQL Server — окрема програма. Вона слухає мережевий порт і розуміє свій протокол — точний формат байтів, які треба надіслати, щоб отримати відповідь.

Питання: чи хочемо ми писати цей протокол самі?

> **npm** — сховище готового коду, яке будь-хто може використати.
> Замість писати драйвер бази самому — беремо готовий.

Три поняття, кожне одним реченням:

| | |
|---|---|
| **пакет** | чийсь готовий код, який робить одну справу |
| **`package.json`** | список пакетів, які потрібні **нашому** проекту |
| **`node_modules`** | папка, куди пакети завантажуються |

⚠ Найважливіше про `node_modules`: **вона не потрапляє в Git**. Її розмір — десятки мегабайт, і вона відтворюється однією командою `npm install` за списком з `package.json`.

Проведи паралель, яка добре працює: `package.json` — це як `schema.sql` для бази. Не самі дані, а **інструкція, як їх відтворити**.

### 12–25 хв. Автентифікація: чому SSMS може, а код не може 🗣

Це технічно, але учні мусять зрозуміти, інакше наступний крок здасться довільним.

Малюй на дошці:

```
   SSMS                          SQL Server
   ┌────────────┐                ┌──────────────┐
   │ я — Windows│  ──────────>   │ бачу, що ти  │
   │ користувач │   локально     │ вже увійшов  │
   │ Student    │                │ у Windows    │
   └────────────┘                └──────────────┘

   Наша програма                 SQL Server
   ┌────────────┐                ┌──────────────┐
   │  Node      │  ──────────>   │ хто ти?      │
   │            │   по мережі    │ логін/пароль │
   └────────────┘                └──────────────┘
```

> SSMS і сервер — на одному комп'ютері, тому сервер бачить, що користувач уже
> увійшов у Windows. Наша програма спілкується з сервером **по мережевому
> протоколу**, і там треба назвати себе явно.

Скажи, що це не незручність, а норма: у реальності програма й база стоять на різних машинах, часто в різних містах.

Два режими автентифікації сервера:

| Режим | Хто може входити |
|---|---|
| Windows Authentication | тільно користувачі Windows |
| **Mixed Mode** | і вони, і власні логіни SQL Server |

Нам потрібен другий. Це налаштування сервера, і його треба ввімкнути один раз.

### 25–38 хв. Секрети не пишуть у код 🗣

Найважливіша частина уроку з точки зору професійної гігієни, і вона зустрінеться знову в блоці 4.

Покажи на проекторі, як **не** треба:

```typescript
const config = {
    user: "student",
    password: "MyPassword123",     // ❌
    server: "localhost",
    database: "Gurtky"
};
```

Питання класу: **що не так?**

Дай наводки, якщо не здогадаються одразу:
- цей файл піде в `git push`
- репозиторій може стати публічним
- пароль залишиться в **історії** Git назавжди, навіть якщо його потім прибрати

> **Правило, яке не має винятків: паролі, ключі й токени ніколи не пишуть у код.**

Рішення:

```
# файл .env — лежить на комп'ютері, у Git НЕ потрапляє
DB_USER=student
DB_PASSWORD=MyPassword123
```

```typescript
const config = {
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
    // ...
};
```

Запуск: `node --env-file=.env app/db.ts`

Три речі, які варто назвати:

1. `.env` додається у `.gitignore` — Git його не бачить
2. натомість у Git кладуть `.env.example` зі структурою, **без значень**
3. `process.env` — те саме `process`, що й `process.argv` у дні 11

⚠ Скажи вголос: у блоці 4 ця сама розмова повернеться щодо деплою, а якщо колись з'явиться AI-ключ — щодо нього теж. Це не навчальна умовність, а те, за що звільняють.

### 38–45 хв. Асинхронність — коротко 🗣

Не давай теорію async/await. Дай **одне правило** й один приклад.

Запит до бази — не миттєвий. Програма надсилає запит і має **чекати** відповіді.

```typescript
const result = await pool.request().query("SELECT * FROM clubs");
```

> `await` означає «зачекай, поки це закінчиться, і тільно потім іди далі».
> Ставиться перед усім, що звертається до бази, файлу або мережі.

І одне обмеження: `await` працює тільно всередині функції, позначеної `async`.

```typescript
async function main() {
    const result = await pool.request().query("SELECT * FROM clubs");
    console.log(result.recordset);
}

main();
```

Скажи прямо: **сьогодні просто пишіть `async` і `await` там, де в зразку.** Розберемось глибше пізніше. Це нормальна навчальна стратегія — спочатку користуватись, потім розуміти.

⚠ Не давай `.then()`, `Promise`, `callback`. Це найшвидший спосіб втратити клас.

## Урок 2 — практика

Учні працюють за `day-15-student.md`. **Скажи на початку, за яким планом працює клас** — основним чи резервним.

### На що дивитись, обходячи клас

1. **`npm install` і мережа.** Якщо registry заблокований — весь урок під загрозою. Тому перевірка до уроку обов'язкова.
2. **`.gitignore`.** Головне, що ти перевіряєш у кінці уроку: чи `.env` **не** видно в `git status`. Якщо видно — пароль піде в Git. Пройди по класу особисто.
3. **Забутий `--env-file=.env`.** Тоді `process.env.DB_USER` буде `undefined`, і підключення провалиться з незрозумілою помилкою.
4. **Забутий `await`.** Програма виведе щось на кшталт `Promise { <pending> }`. Дуже характерний симптом, назви його класу заздалегідь.
5. **Пароль.** Учні придумають `123`. SQL Server відмовить через політику складності. У файлі учня є готовий пароль — вимагай використовувати його, це заощадить 10 хвилин.

### Що показати на проекторі перед початком (5 хвилин)

Пройди повністю: увімкнення Mixed Mode, створення логіна, `.env`, перший запит. Це найдовший показ у курсі, але він заощадить пів уроку.

## Що піде не так

- **Немає прав на перезапуск служби.** Переходь на резервний план. Не витрачай урок.
- **`npm install` не працює.** Симптом: `ETIMEDOUT` або `ENOTFOUND registry.npmjs.org`. Мережа блокує. Резервний план не потребує пакетів взагалі — `fs` вбудований у Node.
- **`Login failed for user 'student'`.** Три причини за частотою: не ввімкнено Mixed Mode; не перезапущено службу; помилка в паролі у `.env`.
- **Помилка про сертифікат.** У конфігурації потрібно `trustServerCertificate: true`. Це в зразку, але хтось пропустить.
- **Забутий `await`** → `Promise { <pending> }`. Найхарактерніша помилка дня.
- **`.env` потрапив у коміт.** Якщо це сталось, пароль уже в історії. Скажи класу: у справжній роботі це означає негайну заміну пароля. Для навчальної бази достатньо виправити `.gitignore` — але розмову провести варто, це запам'ятається.
- **Кириличні дані з бази виводяться нормально.** Тут, на відміну від блоку 1, проблем немає — драйвер працює з `NVARCHAR` коректно. Якщо все ж сміття, справа в терміналі, а не в базі.
