# День 2. Контроль версій. Перший коміт

**Блок 0 — Інструменти**

## Мета дня

Кожна пара має свій репозиторій на GitHub, зробила туди перший коміт і знає ритуал з чотирьох команд. Розуміння моделі Git не потрібне — воно прийде через повторення.

---

## Урок 1 — теорія (без комп'ютерів)

### 0–10 хв. Проблема, яку розв'язує Git 🗣

Не починай з визначення. Почни з болю, який вони знають.

Напиши на дошці список файлів, який кожен бачив:

```
реферат.docx
реферат_виправлений.docx
реферат_виправлений2.docx
реферат_ФІНАЛ.docx
реферат_ФІНАЛ_правки_вчителя.docx
реферат_ФІНАЛ_ФІНАЛ.docx
```

Питання класу:
- Який з них найновіший?
- Що змінилось між третім і четвертим?
- Ви працювали вдвох над рефератом і обидва редагували. Як об'єднати?
- Флешка загубилась. Що робити?

Це чотири проблеми, які Git вирішує: **історія, порівняння, спільна робота, резервна копія**.

### 10–25 хв. Модель: коміт як фотографія 🗣

Малюй на дошці ланцюжок:

```
[коміт 1] ──> [коміт 2] ──> [коміт 3] ──> [коміт 4]
 створили      додали        виправили     додали
 проект        таблицю       помилку       сторінку
```

Тези:

1. **Коміт — це фотографія всього проекту в момент часу**, плюс підпис, хто і коли.
2. **Коміти не замінюють один одного, а вишиковуються в ланцюжок.** Стара версія нікуди не дівається.
3. **Це роблять не автоматично, а свідомо.** Ти сам вирішуєш: «оце — точка, до якої варто вміти повернутись».

### 25–40 хв. Локально і на GitHub 🗣

Найважливіша схема дня. Малюй два кола:

```
   ТВІЙ КОМП'ЮТЕР                      GITHUB
   ┌──────────────┐                ┌──────────────┐
   │  папка pc-07 │  ── push ──>   │  репо pc-07  │
   │  + історія   │  <── pull ──   │  + історія   │
   └──────────────┘                └──────────────┘
```

Тези:

- Git працює **на комп'ютері**, без інтернету. GitHub — це **сайт**, де лежить копія.
- `push` — «відправ мої коміти туди». `pull` — «забери звідти те, чого в мене немає».
- Учитель дивиться саме на копію в GitHub. Немає `push` — робота не існує.
- Напарник працює вдома → зміни з'являються на GitHub → ти робиш `pull` і отримуєш їх.

⚠ Найчастіша плутанина року: **`commit` ≠ `push`**. Скажи це вголос двічі. Коміт зберігає локально, push відправляє. Одне без іншого марне.

### 40–45 хв. Ритуал

Напиши на дошці й скажи, що це висітиме біля кожної машини весь рік:

```
На початку:  git pull

У кінці:     git add .
             git commit -m "що зробили"
             git push
```

## Урок 2 — практика

### Крок 0. Дозавершити встановлення

Якщо вчора не встигли — доробити зараз. Без Git другий урок неможливий.

### Крок 1. Відкрити setup-інструкцію ⌨

Даєш коротке посилання на публічний репо `informatics-11-setup`. Діти відкривають у браузері. Вхід у GitHub не потрібен.

### Крок 2. Клонування ⌨

```
cd %USERPROFILE%\Documents
```

Далі копіюють рядок зі своїм номером комп'ютера з таблиці. ⚠ Тільки копіювати, не набирати — там довгий токен.

Після виконання:

```
dir
```

З'явилась папка `pc-NN`. Це і є їхній проект. Скажи вголос: «ви щойно завантажили проект з інтернету однією командою».

### Крок 3. Підпис ⌨

```
cd pc-NN
git config user.name "PC-NN Прізвище1 Прізвище2"
git config user.email "pc-NN@school.local"
```

⚠ Перевір у кожної пари, що вони **не** написали `--global`. Це та помилка, яку потім важко відловити.

Перевірка:
```
git config user.name
```

### Крок 4. Перший коміт ⌨

Відкрити папку у VS Code:
```
code .
```
(крапка означає «поточна папка» — скажи це, вони спитають)

У VS Code створити файл `README.md`, написати назви гуртка, який хотіли б зробити, і прізвища. Зберегти (**Ctrl + S**).

У терміналі:
```
git status
```

Зупинись тут на хвилину. `git status` покаже червоним `README.md` як змінений. Це перший раз, коли вони бачать, що Git справді слідкує.

```
git add .
git status
```

Тепер той самий файл зелений. Пояснення на пальцях: `add` — це «складаю в коробку те, що хочу зберегти».

```
git commit -m "перший коміт: описали свій гурток"
git push
```

### Крок 5. Побачити результат

Відкрий на проекторі GitHub і покажи репозиторії, які щойно з'явились. Це момент, заради якого варто зробити паузу — вони бачать, що їхня робота реально десь є.

### Крок 6. Другий коміт ⌨

Не закінчуй уроку на одному коміті. Зроби другий, щоб ланцюжок став ланцюжком:

Дописати в `README.md` ще один рядок → зберегти →
```
git add .
git commit -m "додали опис занять"
git push
git log --oneline
```

`git log` покаже два рядки. Поверни їх до схеми з дошки: «ось ваш ланцюжок».

---

## ⭐ Зіркове завдання

Змінити файл, зробити `git diff` до `add` і пояснити, що означають `+` і `−` у виводі.

Друге: подивитись на GitHub на сторінку коміту і знайти, де там видно точний час і підпис.

## Що піде не так

- **Вставка в термінал.** Ctrl+V у старому `cmd` не працює — потрібна права кнопка миші. Покажи це до того, як вони спробують.
- **Відкрився Vim.** Якщо хтось напише `git commit` без `-m`, відкриється редактор, з якого не вийти. Вихід: `:q` + Enter. Впиши це в `errors.md` і скажи заздалегідь.
- **`nothing to commit`.** Забули зберегти файл у VS Code. Найчастіша причина.
- **Push відхилено.** Якщо ти щойно щось коммітив у їхній репо з дому. Рішення: `git pull`, потім `git push`.
- **Хтось клонував не в ту папку.** `dir`, знайти, перенести або клонувати заново — це швидше, ніж розбиратись.
