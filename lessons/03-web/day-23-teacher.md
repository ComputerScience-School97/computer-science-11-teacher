## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–12 хв. Що таке DOM 🗣

Почни з того, що вони вже бачили. Відкрий F12 → Elements і покажи дерево.

Питання класу: **це той самий текст, що в файлі, чи щось інше?**

Відповідь: інше. І це головна ідея дня.

```
   ФАЙЛ index.html            БРАУЗЕР
   ┌──────────────┐          ┌──────────────────┐
   │ текст HTML   │  ───>    │ дерево об'єктів  │
   │              │  читає   │ (DOM)            │
   └──────────────┘          └──────────────────┘
                                     │
                                     └─> малює сторінку
```

> **DOM** (об'єктна модель документа) — це сторінка, представлена як **дерево
> об'єктів**, з яким можна працювати кодом.

Три наслідки, які варто назвати явно:

1. **Файл читається один раз.** Далі браузер працює з деревом у пам'яті.
2. **Змінюючи дерево, ти змінюєш сторінку** — одразу, без перезавантаження.
3. **Після F5 усе повертається**, бо дерево будується з файлу заново.

⚠ Проведи паралель із блоком 2, вона точна й допомагає:

> Об'єкт із дня 13 мав поля: `club.name`, `club.room`.
> Елемент сторінки — теж об'єкт із полями: `element.textContent`,
> `element.className`. Це та сама ідея.

### 12–25 хв. Знайти елемент і змінити його 🗣

Пиши на проекторі, показуй результат.

```javascript
const title = document.querySelector("h1");
title.textContent = "Нова назва";
```

| Частина | Що означає |
|---|---|
| `document` | уся сторінка |
| `querySelector("h1")` | знайти **перший** елемент за селектором CSS |
| `textContent` | текст усередині елемента |

⚠ Головне спрощення, яке варто підкреслити: **у `querySelector` пишуть той самий селектор, що в CSS**. `"h1"`, `".club"`, `"#search"`. Нічого нового вчити не треба.

Два методи, більше сьогодні не потрібно:

```javascript
document.querySelector(".club")      // перший знайдений
document.querySelectorAll(".club")   // ВСІ знайдені, як список
```

Що можна змінювати:

```javascript
element.textContent = "текст";
element.style.display = "none";
element.classList.add("active");
element.classList.remove("active");
```

⚠ Скажи важливу річ про останні два: **краще керувати класами, ніж стилями напряму**. Причина — оформлення залишається в CSS, де йому місце. Це продовження ідеї дня 20.

### 25–35 хв. Події 🗣

```javascript
const button = document.querySelector("#toggle");

button.addEventListener("click", function() {
    console.log("Натиснули");
});
```

Формулювання, яке працює:

> `addEventListener` — це «коли станеться **оце**, виконай **цю функцію**».
> Функція лежить і чекає. Вона виконається не зараз, а коли користувач щось зробить.

Це нова для них ідея. У блоці 2 програма виконувалась згори вниз і закінчувалась. Тут вона **чекає**.

Події, яких достатньо:

| Подія | Коли спрацьовує |
|---|---|
| `click` | клікнули |
| `input` | змінили текст у полі — **на кожну літеру** |
| `change` | змінили значення й пішли з поля |
| `submit` | надіслали форму |

⚠ `input` проти `change` — тонкість, яка важлива для пошуку. `input` дає живий пошук під час набору, `change` — тільно після виходу з поля. Для пошуку потрібен `input`.

### 35–45 хв. Дані в коді, сторінка з коду 🗣

Головний перехід дня, і він готує весь залишок блоку.

Досі гуртки були **вписані в HTML руками**. Питання класу: **що буде, коли гуртків стане сорок?**

Ті самі проблеми, що в дні 3 з таблицею-жахом і в дні 14 з дублюванням коду: правити в багатьох місцях, легко помилитись.

Рішення:

```javascript
const clubs = [
    { name: "Програмування", room: "215", weekday: "понеділок", max: 14, enrolled: 9 },
    { name: "Робототехніка",  room: "108", weekday: "середа",    max: 10, enrolled: 10 }
];

const container = document.querySelector("#clubs-list");

for (const club of clubs) {
    container.innerHTML += `
        <article class="club">
            <h3>${club.name}</h3>
            <p>Кабінет ${club.room}, ${club.weekday}. Місць: ${club.max}</p>
        </article>
    `;
}
```

Три речі, які варто назвати:

1. **Масив об'єктів — той самий, що в дні 13.** Нічого нового.
2. **Шаблонні рядки — ті самі, що в дні 11.** Зворотні апострофи й `${}`.
3. **`innerHTML`** — вставити HTML як текст. Браузер розбере його в дерево.

І головна теза, яка веде в день 24:

> Тепер HTML **будується з даних**. Замініть цей масив на дані з бази —
> і сторінка сама покаже те, що в базі. Це і зробимо на наступному уроці.

⚠ Про `innerHTML` варто сказати обережно: він зручний, але небезпечний, якщо туда потрапляє текст від користувача. Не заглиблюйся зараз — це зіркове завдання, і повернемось у дні 25 при валідації.

## Урок 2 — практика

Учні працюють за `day-23-student.md`. Роблять: генерацію списку гуртків з масиву, живий пошук, фільтр за днем тижня, перемикач теми.

### Технічний момент

Скрипт підключається **в кінці `<body>`**:

```html
    <script src="app.js"></script>
</body>
```

⚠ Не в `<head>`. Причина: скрипт у `<head>` виконається до того, як існують елементи сторінки, і `querySelector` поверне `null`. Це найчастіша помилка дня, і вона дає незрозумілу помилку.

Файл — **`web/app.js`**, звичайний JavaScript.

### На що дивитись, обходячи клас

1. **Скрипт у `<head>`.** Розібрано вище. Симптом: `Cannot read properties of null`.
2. **Забутий `#` або `.` у селекторі.** `querySelector("clubs-list")` шукає **тег** з такою назвою. Повертає `null`.
3. **`innerHTML +=` у циклі.** Працює, але переписує весь HTML на кожній ітерації. Для десяти гуртків нормально, для тисячі — ні. Правильно накопичувати в рядку й вставити один раз. Це в зірковому, але варто сказати, коли хтось спитає.
4. **Не дивляться в консоль.** Головна нова навичка дня. Помилки JavaScript **не видно на сторінці** — вони в F12 → Console. Половина класу сидітиме над «нічого не працює», не подивившись туда.

### Що показати на проекторі перед початком (5 хвилин)

1. F12 → **Console**. Набери `document.querySelector("h1").textContent = "Тест"` і натисни Enter. Сторінка змінилась.
2. Тепер зроби навмисну помилку в коді й покажи, як вона виглядає в Console: назва файлу, номер рядка, опис.

Друге важливіше за перше. Скажи прямо: **консоль — перше місце, куда дивитись, коли скрипт не працює.**

## ⭐ Зіркове завдання

У файлі учня: `createElement` замість `innerHTML`, сортування списку кнопками, кілька фільтрів разом, `localStorage`, рекурсивний обхід DOM.

⚠ `localStorage` працює у файлі, відкритому через `file://`, у Chrome — але не завжди. Якщо не спрацює, це нормальний привід поговорити про обмеження безпеки браузера.

## Що піде не так

- **Скрипт у `<head>`.** Найчастіша помилка. Скажи на початку.
- **Не дивляться в консоль.** Друга за частотою причина застрягання. Наполягай.
- **`querySelector` повертає `null`.** Причини: скрипт у `<head>`; помилка в селекторі; забутий `#`/`.`.
- **Помилка в шаблонному рядку.** Звичайні лапки замість зворотних апострофів — і `${club.name}` виведеться як текст. Симптом характерний, легко впізнається.
- **Питання про TypeScript.** Прозвучить обов'язково. Відповідь: браузер не розуміє TypeScript без збірки; у дні 24 типи повернуться на сервері.
- **Фільтр працює один раз.** Якщо фільтрувати, приховуючи елементи, а потім не показувати їх назад — список «тає». Класична помилка. Рішення в завданні: щоразу перемальовувати список з нуля, а не приховувати.
