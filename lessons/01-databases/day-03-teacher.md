### 25–35 хв. Модель даних 🗣

> **Модель даних** — спосіб, у який ми домовились описувати дані: з чого вони складаються і як пов'язані.

Основні моделі, коротко, з одним прикладом на кожну:

| Модель | Як виглядає | Де зустрічається |
|---|---|---|
| **Реляційна** | таблиці, зв'язані між собою | більшість систем: банки, школи, магазини |
| **Документна** | документи-«картки» довільної структури | MongoDB, каталоги товарів |
| **Іерархічна** | дерево | файлова система, налаштування Windows |
| **Графова** | вузли й зв'язки | соцмережі («друзі друзів») |

Ми весь рік працюємо з реляційною, бо це стандарт. Документну подивимось окремо в кінці блоку для порівняння.

### 35–45 хв. Що таке СКБД 🗣

> **СКБД** (система керування базами даних) — програма, яка зберігає дані й обслуговує запити до них. База даних — це дані. СКБД — програма, що ними керує.

Аналогія, яка працює: бібліотека і бібліотекар. Книги — база, бібліотекар — СКБД.

Функції СКБД, кожну з прикладом «а якби її не було»:

| Функція | Якби не було |
|---|---|
| Зберігання і структура | сам придумуй формат файлу |
| Мова запитів | пиши програму для кожного питання до даних |
| Обмеження цілісності | у полі «клас» з'явиться «немає» |
| Багатокористувацький доступ | двоє записують одночасно → дані зіпсовані |
| Резервне копіювання, транзакції | збій живлення посеред запису → все втрачено |

Назви приклади СКБД: Microsoft SQL Server, PostgreSQL, MySQL, Oracle, SQLite.

Ми працюємо з **Microsoft SQL Server**. Скажи, чому саме він: це промислова СКБД, яку реально використовують в українських компаніях, і навички переносяться на роботу без перенавчання. Мова запитів (SQL) практично однакова у всіх — вивчивши одну, розберешся з будь-якою.

Одразу введи два поняття, бо вони плутаються весь блок:
- **сервер** — програма, яка працює у фоні на комп'ютері й тримає всі бази
- **база** — один конкретний набір таблиць на цьому сервері (`GurtkyDemo`, потім `Gurtky`)

Аналогія: сервер — це шафа, база — одна папка в ній. На одному сервері десятки баз.

### Крок 1. Отримати базу та інструмент

Скрипт `project/db/01-create-demo.sql` уже лежить у курсовому репо — учні беруть його звідти.

База не роздається файлом: учні **створюють її самі**, виконавши скрипт. Це краще, ніж готовий файл: вони бачать `CREATE TABLE` до того, як писатимуть його самі на дні 6, і не залежать від флешки.

Інструмент: **SSMS** (встановлений на дні 1). VS Code для SQL не використовуємо.

⚠ Перевір на одній машині до уроку весь ланцюжок: SSMS підключається → скрипт виконується → `SELECT` дає результат. Особливо звірку, чи виводиться кирилиця, а не `??????`.

**Три речі про SSMS, які варто показати на проекторі перед практикою** (3 хвилини, не більше):
- **Object Explorer** ліворуч: сервер → Databases → база → Tables → Columns. Це дерево, як папки
- **Ctrl + N** — новий аркуш для запитів, **F5** — виконати
- ⚠ **F5 без виділення виконує весь аркуш.** Щоб один запит — виділити мишкою. Це головна плутанина уроку

⚠ Головна технічна деталь блоку: у SQL Server український текст потрібно писати з префіксом `N`: `N'Іваненко'`. Без нього літери псуються. Скажи це на першому ж запиті й повторюй увесь блок.

### Крок 4. Перші запити ⌨

**Ctrl + N** — новий аркуш. ⚠ Одразу **File → Save As** у папку `sql` свого проекту, під назвою `day03.sql`. Якщо не зберегти в папку проекту, Git цієї роботи не побачить.

Кожен аркуш починається з двох рядків, інакше запит піде не в ту базу:

```sql

```

Альтернатива — вибрати базу у випадному меню зверху. Покажи обидва способи, але вимагай писати `USE`: файл має працювати сам по собі.

```sql

-- 2. Всі учні

-- 3. Тільки назви гуртків
```

⚠ Тут покажи **виконання одного запиту**: виділити його мишкою → **F5**. Без виділення виконається весь аркуш. Це найбільша плутанина уроку, покажи особисто кожній парі.

Обов'язково розбери запит 3 і 4 вголос: `*` означає «всі поля», а можна перелічити потрібні. Питання класу: чому запит 3 корисніший за 1, якщо в таблиці 30 полів?

## Що піде не так

- **Не підключається до сервера.** Найчастіше — неправильне ім'я. Мала б бути записана на дні 1; якщо ні, пробувати по черзі. Друга причина — помилка про сертифікат, лікується `Encryption: Optional` у вікні Connect to Server.
- **Зберегли аркуш не туди.** SSMS за замовчуванням пропонує свою папку в `Documents`, а не папку проекту. Половина класу збереже туди, і `git status` нічого не покаже. Перевір це особисто в перших трьох пар, далі вони підкажуть одне одному.
- **Кирилиця як `??????`.** Забули `N` перед текстом. Перевір це на своєму прикладі першим, поки не почали писати самі.
- **Виконався весь файл замість одного запиту.** Ctrl+Shift+E виконує все. Щоб один — виділити мишкою. Покажи це особисто кожній парі, інакше половина уроку піде на здивування.
- **Забули крапку з комою.** Розширення часто виконує й без неї, але привчай ставити одразу.
- **Пишуть у нижньому регістрі.** `select * from clubs` працює. Не забороняй, але сам завжди пиши ключові слова великими — вони скопіюють стиль.
- **Запустили курсор не на тому рядку.** Розширення виконує запит, на якому стоїть курсор. Половина «нічого не працює» — це саме воно.
- **Скрипт виконали двічі.** Нічого страшного: він починається з видалення бази, тому просто перестворить її. Скажи це заздалегідь, щоб не боялись.
- **База не з'явилась у дереві.** Object Explorer не оновлюється сам. Права кнопка по `Databases` → **Refresh**. Це питання буде в кожної пари.
- **`GO` викликає питання.** Скажи коротко: розділювач між частинами скрипта, особливість SQL Server. Не заглиблюйся.
