# День 17. Тематична робота № 1

**Оцінювання за блоки 1–2**

## Формат

**Парна робота, два уроки (90 хвилин), одна здача на комп'ютер, спільна оцінка на обох.**

Це рішення має плюси й один мінус, і мінус варто закрити свідомо.

**Плюси:** робота відповідає тому, як клас працював увесь семестр; можна дати задачу реального обсягу, а не «мінімум на 45 хвилин»; жоден учень не залишається без комп'ютера.

**Мінус:** якщо в парі один сильний і один слабкий, обидва отримають однакову оцінку, і ти не побачиш різниці.

### Як закрити мінус за 15 хвилин

Додай **усну перевірку** в кінці другого уроку. По 2 хвилини на пару, питання кожному окремо:

1. Показуєш **їхній** запит із частини D2 (`JOIN`) і питаєш першого: *що робить цей рядок з `ON`? Що буде, якщо його прибрати?*
2. Показуєш їхню функцію з частини F і питаєш другого: *чому тут `return`, а не `console.log`? Що станеться, якщо поміняти?*

Це не окрема оцінка. Це право знизити спільну оцінку на 1–2 бали конкретному учню, який не може пояснити роботу, яку здав. Скажи класу про усну перевірку **на початку роботи** — це різко підвищує участь обох.

### Варіанти

У файлі учня **чотири варіанти** з різними предметними областями. Роздай так, щоб сусідні комп'ютери отримали різні — це стримує підглядання.

Розподіл склади заздалегідь: п'ять хвилин роботи вдома.

### Чия робота

Файли називаються з прізвищами **обох**: `exam-1/ivanenko-petrenko.sql`

## Критерії оцінювання

### A. Модель предметної області — 2 бали

| | |
|---|---|
| 2 | чотири сутності (включно з таблицею-посередником), у кожної ключ, усі зв'язки з множинністю **і** обґрунтуванням |
| 1 | сутності є, але множинність не всюди, або немає обґрунтування, або пропущено зв'язок M:N |
| 0 | менше трьох сутностей, або зв'язки не описані |

### B. Створення таблиць — 3 бали

| | |
|---|---|
| 3 | чотири таблиці; `PRIMARY KEY` з `IDENTITY`; коректні типи (`NVARCHAR`!); `NOT NULL` де треба; **два** робочі зовнішні ключі в таблиці-посереднику; є щонайменше одне з `UNIQUE`/`CHECK`/`DEFAULT` |
| 2 | усе працює, зв'язок M:N реалізований, але обмеження мінімальні |
| 1 | таблиці створюються, але немає зв'язку M:N або є `VARCHAR` замість `NVARCHAR` |
| 0 | скрипт не виконується |

⚠ `VARCHAR` замість `NVARCHAR` — не дрібниця, це втрата даних. Знижуй.

### C. Дані — 1 бал

| | |
|---|---|
| 1 | дані в усіх чотирьох таблицях, зв'язки заповнені, `N` перед українським текстом |
| 0 | даних немає, або кирилиця зіпсована, або таблиця-посередник порожня |

### D. Запити — 3 бали

Чотири запити, оцінка сумарна:

| | |
|---|---|
| 3 | усі чотири працюють і дають осмислений результат |
| 2 | працюють три, включно з `JOIN` по двох таблицях |
| 1 | працює тільно `WHERE` |
| 0 | запити не виконуються |

### E. Читання коду — 1 бал

| | |
|---|---|
| 1 | правильно описано, що робить функція, **і** знайдено помилку |
| 0 | опис неправильний або помилка не знайдена |

### F. Програма — 2 бали

| | |
|---|---|
| 2 | усі три функції працюють, типи параметрів і повернення вказані, звіт виводиться |
| 1 | працює частина функцій, або немає типів, або функція виводить замість повертати |
| 0 | програма не запускається |

## Як перевіряти

Не читай код очима — **виконуй його**.

1. `git pull` у репо пари
2. Візьми `exam-1/*.sql`, виконай у SSMS **повністю, з нуля**
3. Скрипт не виконується — це вже відповідь по частині B
4. Виконай їхні запити, подивись на результати
5. Запусти `node exam-1/*.ts`

⚠ Головний критерій, який ловить копіювання: **скрипт має виконуватись з нуля на чистому сервері**. Хто копіював фрагменти не розуміючи, отримає скрипт із посиланнями на неіснуючі таблиці або з неправильним порядком створення.

## Що піде не так

- **Не хватить часу.** Найімовірніше. У завданні є явний порядок і позначено, що A–D важливіші за E–F. Скажи вголос: **краще чотири частини добре, ніж шість наполовину.**
- **Забудуть `git push`.** І робота залишиться на машині. Напиши команду на дошці великими літерами й нагадай за 10 хвилин до кінця. Це найдурніша причина втратити оцінку.
- **Один робить, другий сидить.** Саме тому потрібна усна перевірка, і саме тому про неї треба сказати на початку. Додатково: у завданні прописано міняти того, хто друкує, між частинами.
- **Скопіюють свій `schema.sql` цілком.** Дозволено, але предметна область інша, тому просте копіювання не спрацює. Для цього варіанти й потрібні.
- **Технічна проблема з'їдає час.** Не підключається сервер — дай надолужити або перенеси пару на інший день. Не карай за інфраструктуру.
- **Частина F не запускається через `--env-file`.** У частині F дані задані в коді, тому `--env-file` не потрібен. Хтось усе одно спробує. Скажи: `node exam-1/файл.ts` без нічого.

## Пункти держпрограми

Робота перевіряє накопичено:

- *Вміє визначати сутності, атрибути, зокрема ключові, а також зв'язки між сутностями в предметній області.*
- *Класифікує зв'язки між сутностями за множинністю та обов'язковістю.*
- *Реалізує модель предметної області засобами СКБД. Забезпечує підтримку обмежень цілісності.*
- *Реалізує зв'язки усіх типів множинності.*
- *Вводить дані в базу, зокрема про зв'язки між записами.*
- *Створює та виконує запити на вибірку даних з однієї та кількох зв'язаних таблиць. Виконує групування даних.*
- *Реалізує базові алгоритми засобами мови програмування.*
- *Пояснює структуру алгоритму.*
- *Оцінює реалізацію системи відповідно до вимог проекту.*
