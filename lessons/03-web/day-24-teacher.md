## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–12 хв. Чому файл у браузері — це не сайт 🗣

Постав питання: **чим те, що ви робите, відрізняється від справжнього сайту?**

Подивись на адресний рядок на проекторі:

```
file:///C:/Users/Student/Documents/pc-07/web/index.html
```

Порівняй із:

```
https://school.example.com/clubs
```

Розберіть різницю:

| | `file://` | `https://` |
|---|---|---|
| Хто віддає файл | сама файлова система | **сервер** |
| Чи можна відкрити з іншого комп'ютера | ні | так |
| Чи можна отримати дані з бази | ні | так |
| Частина можливостей браузера | заблокована | працює |

> Сайт — це не файли. Сайт — це **програма, яка відповідає на запити**.

Поверни до дня 18, де ви малювали схему запит-відповідь. Сьогодні ви напишете **другу половину** цієї схеми.

### 12–25 хв. Що робить сервер 🗣

Малюй на дошці:

```
   БРАУЗЕР                          ВАШ СЕРВЕР                    БАЗА
   ┌──────────┐                    ┌────────────┐              ┌──────────┐
   │          │  GET /             │            │              │          │
   │          │ ─────────────────> │ віддає     │              │          │
   │          │ <───── index.html  │ файли      │              │          │
   │          │                    │            │              │          │
   │          │  GET /api/clubs    │            │  SELECT      │          │
   │  app.js  │ ─────────────────> │ питає базу │ ───────────> │  Gurtky  │
   │          │ <───── JSON        │            │ <─── рядки   │          │
   └──────────┘                    └────────────┘              └──────────┘
```

Ключова теза:

> Сервер робить **дві різні речі**: віддає файли сторінки й відповідає на запити за даними.

Це два різні типи адрес, і різницю варто закріпити:

| Адреса | Що повертає | Для кого |
|---|---|---|
| `/` | HTML-сторінку | для людини |
| `/api/clubs` | JSON із даними | для програми |

⚠ Питання класу для перевірки: якщо відкрити `/api/clubs` прямо в браузері — що побачиш? (Відповідь: текст JSON. Це не помилка. Просто це адреса не для людини.)

### 25–35 хв. JSON 🗣

> **JSON** — текстовий формат для передачі даних. Виглядає майже точно так,
> як масив об'єктів у JavaScript.

```json
[
  {"name": "Програмування", "room": "215", "max": 14, "enrolled": 9},
  {"name": "Робототехніка",  "room": "108", "max": 10, "enrolled": 10}
]
```

Чому саме він: його розуміє будь-яка мова програмування, він читається людиною, і він компактний.

Три відмінності від JavaScript, які варто назвати:

| | JavaScript | JSON |
|---|---|---|
| Ключі | можна без лапок | **завжди в подвійних лапках** |
| Лапки | одинарні або подвійні | **тільно подвійні** |
| Коментарі | можна | **не можна** |

Скажи, що в резервному плані дня 15 вони цей формат уже бачили — там дані експортувались із SQL Server через `FOR JSON PATH`.

### 35–45 хв. REST і ендпоінти 🗣

Не давай теорію REST. Дай **домовленість про іменування**, бо саме це має практичний сенс.

> **Ендпоінт** — одна адреса на сервері, яка щось робить.

```
GET    /api/clubs        отримати список гуртків
GET    /api/clubs/3      отримати гурток №3
POST   /api/clubs        додати новий гурток
PUT    /api/clubs/3      змінити гурток №3
DELETE /api/clubs/3      видалити гурток №3
```

Дві речі, які варто підкреслити:

**1. Адреса — це іменник, а не дієслово.** Не `/api/getClubs`, а `/api/clubs`. Що робити — вказує **метод** (`GET`, `POST`), а не адреса.

**2. Методи вони вже знають з іншого боку.** Проведи паралель, вона точна:

| HTTP | SQL із блоку 1 |
|---|---|
| `GET` | `SELECT` |
| `POST` | `INSERT` |
| `PUT` | `UPDATE` |
| `DELETE` | `DELETE` |

Це не випадковий збіг — обидві системи описують ті самі чотири дії з даними.

Сьогодні робимо тільно `GET`. `POST` буде в дні 25.

## Урок 2 — практика

Учні працюють за `day-24-student.md`.

### Технічні моменти

**Express** встановлюється через npm. Якщо мережа блокує npm — у файлі учня є резервний варіант на вбудованому модулі `node:http`. Він трохи довший, але не потребує жодного пакета.

**Сервер віддає й статику.** `app.use(express.static("web"))` — тоді сайт відкривається на `localhost:3000`, і `app.js` може звертатись до `/api/clubs`. Це прибирає обмеження `file://`, з якими вони наткнулись у дні 23 на `localStorage`.

**Запуск:** `node --env-file=.env app/server.ts`. Сервер не завершується сам — він чекає запитів. Зупинка **Ctrl + C**.

⚠ Це нове відчуття для класу: досі всі програми закінчувались. Скажи заздалегідь, що термінал «зависне» — і це правильно.

### На що дивитись, обходячи клас

1. **Забутий `await` перед `loadClubs()`.** Симптом характерний: у браузері приходить `{}` замість масиву. Впізнається одразу.
2. **Порт зайнятий.** `EADDRINUSE` означає, що попередній запуск не зупинено. Ctrl + C у тому терміналі, або новий порт.
3. **Відкривають файл замість сервера.** Сторінка відкрита через `file://`, а не `localhost:3000`, і `fetch` не працює. Найчастіша плутанина другої половини уроку.
4. **Порядок у `server.ts`.** `express.static` має стояти **після** оголошення API-маршрутів або поруч — якщо статика перехопить усе першою, `/api/clubs` може не спрацювати. У зразку порядок правильний, але хтось переставить.

### Що показати на проекторі перед початком (5 хвилин)

1. Запусти сервер, відкрий `localhost:3000/api/clubs` у браузері. Хай побачать сирий JSON.
2. Відкрий F12 → **Network**, перезавантаж сторінку, знайди в списку запит `clubs`, клікни на нього і покажи вкладки **Headers** і **Response**.

Друге важливіше. Це головний інструмент налагодження API, і вони будуть ним користуватись до кінця курсу.

## Що піде не так

- **npm заблокований.** Резервний варіант на `node:http` є у файлі учня. Він працює без жодного пакета.
- **Сторінка відкрита через `file://`.** Розібрано вище. Симптом: `fetch` падає, у консолі помилка про CORS або про протокол. Перевіряй адресний рядок першим.
- **Сервер не перезапущено після правки.** На відміну від сторінки, сервер не перечитує файл сам. Ctrl + C, потім запустити знову. Це дратує весь урок; скажи заздалегідь.
- **Забутий `await`** → `{}` замість даних.
- **База недоступна.** Якщо SQL Server не запущений, сервер віддасть помилку. У зразку є `try/catch` із дня 16 — саме для цього він і був потрібен. Гарний момент це назвати.
- **Час.** День насичений: npm, сервер, JSON, `fetch`. Якщо не хватить — зіркові завдання можна перенести, але `fetch` у частині 5 зробити обов'язково, інакше день не має завершення.
