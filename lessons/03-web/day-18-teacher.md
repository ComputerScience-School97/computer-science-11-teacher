## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–15 хв. Що відбувається при натисканні Enter 🗣

Постав питання прямо: **ви набрали адресу й натиснули Enter. Що сталося?**

Збери версії класу. Потім розбирай на дошці по кроках. Малюй схему:

```
   БРАУЗЕР                                    СЕРВЕР
   ┌──────────┐                            ┌──────────┐
   │          │  1. запит: дай /clubs      │          │
   │  Chrome  │  ─────────────────────>    │  Node    │
   │          │                            │          │
   │          │  2. відповідь: ось HTML    │          │
   │          │  <─────────────────────    │          │
   └──────────┘                            └──────────┘
       │
       3. браузер малює сторінку
```

Ключові тези, кожну одним реченням:

1. **Браузер — програма на твоєму комп'ютері.** Він нічого не знає про сайт, поки не спитає.
2. **Сервер — програма на іншому комп'ютері.** Він чекає запитів і відповідає.
3. **Це не потік, а обмін.** Запит — відповідь. Далі з'єднання закінчується.
4. **Браузер отримує текст, а не картинку.** HTML — це текст. Малює сторінку сам браузер.

⚠ Останнє — головне непорозуміння дня. Скажи явно: сервер не надсилає зображення сторінки. Він надсилає **опис**, а як він виглядатиме, вирішує браузер. Саме тому один сайт виглядає по-різному на телефоні й комп'ютері.

Проведи паралель із блоком 2, вона точна:

> Ви це вже робили. У дні 15 ваша **програма** була клієнтом, а SQL Server — сервером.
> Програма надсилала запит, сервер відповідав. Тепер клієнт — браузер.

### 15–25 хв. HTTP, домени, хостинг 🗣

Три поняття, кожне через приклад, а не визначення.

**HTTP** — правила, за якими браузер і сервер розмовляють. Розбери адресу на дошці:

```
https://school.example.com/clubs?day=monday
└─┬─┘   └────────┬────────┘└─┬──┘└────┬────┘
протокол      домен        шлях   параметри
```

| Частина | Що означає |
|---|---|
| `https` | протокол; `s` означає, що обмін зашифрований |
| `school.example.com` | **домен** — ім'я, за яким знаходять сервер |
| `/clubs` | **шлях** — що саме просимо в цього сервера |
| `?day=monday` | **параметри** — уточнення до запиту |

⚠ Параметри варто підкреслити: це те саме, що `process.argv` у дні 11 або параметр функції в дні 14. Значення, яке передається зовні. У дні 25 вони будуть їх читати.

**Домен і хостинг** — коротко, одним прикладом:

> Домен — це адреса. Хостинг — це будинок за цією адресою.
> Домен можна перенаправити на інший хостинг, як переїзд.

**Код відповіді** — назви три, більше не потрібно:

| | |
|---|---|
| `200` | усе гаразд |
| `404` | сервер не знайшов, що просили |
| `500` | сервер зламався при обробці запиту |

Скажи, що `500` вони побачать у дні 25, коли їхній власний сервер упаде. І це нормально.

### 25–33 хв. Види сайтів і цільова аудиторія 🗣

Держпрограма вимагає, і 8 хвилин на це достатньо. Роби через обговорення, не через список.

Питання класу: назвіть п'ять сайтів, якими користуєтесь. Записуй на дошці. Далі для кожного питай **чого від нього хоче користувач**:

| Тип | Чого хоче користувач | Що з цього випливає для розробника |
|---|---|---|
| Пошук / довідка | швидко знайти відповідь і піти | швидкість важливіша за красу |
| Магазин | порівняти й купити | фото, ціна, кнопка мають бути очевидні |
| Соцмережа | подивитись, що нового | нескінченна лінта, оновлення без перезавантаження |
| Сервіс / кабінет | зробити конкретну дію | ясні форми, зрозумілі помилки |
| Новини / блог | почитати | читабельний текст, великий шрифт |

Тепер поверни до їхнього проекту:

> Ваш сайт — який це тип? Хто його користувач?

Розберіть це вголос. Виявиться, що користувачів **два**: учень, який шукає гурток і записується, і вчитель, який дивиться списки. У них різні потреби. Це відкриття, і воно знадобиться в дні 27 при формулюванні вимог.

### 33–45 хв. HTML: структура, а не вигляд 🗣

Головна теза перед синтаксисом:

> HTML описує **структуру** документа: що тут заголовок, що абзац, що список.
> Як це виглядає — окрема справа, і про неї день 20.

Пиши на проекторі й запускай:

```html
<!DOCTYPE html>
<html lang="uk">
<head>
    <meta charset="utf-8">
    <title>Гуртки школи</title>
</head>
<body>
    <h1>Гуртки нашої школи</h1>
    <p>Обери гурток за інтересами.</p>
</body>
</html>
```

| Частина | Що означає |
|---|---|
| `<!DOCTYPE html>` | «це сучасний HTML» |
| `<html lang="uk">` | документ, мова українська |
| `<head>` | службова інформація — її **не видно** на сторінці |
| `<meta charset="utf-8">` | ⚠ **кодування**; без нього кирилиця зламається |
| `<title>` | назва у вкладці браузера |
| `<body>` | те, що видно |

⚠ `<meta charset="utf-8">` — це та сама проблема, що `N'текст'` у SQL і термінал у Node. Скажи це вголос: **третє місце в курсі, де кодування може зіпсувати українські літери**. Клас це вже двічі проходив, і паралель допомагає запам'ятати.

**Тег і елемент:**

```html
<p>Текст абзацу</p>
└┬┘              └┬┘
відкриваючий   закриваючий
```

Скажи, що майже всі теги парні, і забутий закриваючий — головна помилка початківців.

## Урок 2 — практика

Учні працюють за `day-18-student.md`.

### Технічний момент: як дивитись результат

Сторінку відкривають **прямо у браузері з файлу**: права кнопка по файлу у VS Code → `Reveal in File Explorer` → двічі клікнути. Або перетягнути файл у вікно браузера.

Цикл роботи: **змінив → Ctrl + S → F5 у браузері**.

⚠ Не встановлюй розширення типу Live Server — на цьому етапі воно зайве й додає ще одну сутність, яка може не працювати. Справжній сервер з'явиться в дні 25, і тоді це буде осмислено.

### На що дивитись, обходячи клас

1. **Забутий `<meta charset="utf-8">`.** Симптом — сміття замість кирилиці. Буде в кількох парах, попередь заздалегідь.
2. **Незакриті теги.** Сторінка не ламається повністю, але виглядає дивно — наприклад, весь текст після незакритого `<h1>` стає заголовком. Дуже наочно.
3. **Файл не в тій папці.** Вимагай `web/index.html` — це буде корінь сайту весь блок.
4. **Кожен рядок в окремому `<p>`.** HTML ігнорує переходи на новий рядок у коді. Це відкриття для класу, і воно передбачене в завданні.

### Що показати на проекторі перед початком (3 хвилини)

Відкрий будь-який реальний сайт, натисни **F12** → **Elements**. Покажи, що весь інтернет — це такий самий HTML, який вони зараз писатимуть. Потім змінь якийсь текст прямо в інструментах і покажи, що на сторінці він змінився.

Це найсильніший момент дня мотиваційно. Обов'язково скажи, що зміни живуть тільно в їхньому браузері й зникнуть при перезавантаженні.

## Що піде не так

- **Кодування.** Розібрано вище. Найчастіша проблема.
- **«А де кольори?».** Питання прозвучить у перші 10 хвилин, бо сторінка виглядає як текст із Word 1995 року. Відповідь: HTML — це структура, оформлення в дні 20. Скажи це наперед, щоб не розчаровувались.
- **Копіюють HTML з інтернету.** Інтернету немає, але хтось згадає з попереднього досвіду `<center>`, `<font>` або таблиці для верстки. Це застарілі теги. Не сварись, просто скажи, що зараз так не роблять, і чому — оформлення окремо від структури.
- **Плутають `<head>` і `<h1>`.** Схожі на слух. Розділи явно: `<head>` — службове, невидиме; `<h1>` — видимий заголовок.
- **Забувають зберегти перед F5.** Та сама помилка, що в блоці 2. Нагадай цикл.
