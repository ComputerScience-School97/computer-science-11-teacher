### 8–20 хв. Агрегатні функції 🗣

Спочатку без груп — по всій таблиці.

> **Агрегатна функція** — функція, яка з багатьох рядків робить **одне** значення.

| Функція | Що робить |
|---|---|
| `COUNT(*)` | скільки рядків |
| `SUM(поле)` | сума значень |
| `AVG(поле)` | середнє |
| `MIN(поле)` / `MAX(поле)` | найменше / найбільше |

Одна пастка, яку варто розібрати одразу, бо вона неочевидна:

```sql
SELECT COUNT(*) FROM clubs;              -- 8: усі рядки
SELECT COUNT(teacher_id) FROM clubs;     -- 7: тільки НЕ порожні
```

> `COUNT(*)` рахує рядки. `COUNT(поле)` рахує **заповнені** значення, пропускаючи `NULL`.

Це не дрібниця. Питання класу: як за допомогою цих двох запитів дізнатись, скільки гуртків **без** керівника? (Відповідь: різниця. Або `LEFT JOIN` з дня 8 — обидва шляхи правильні.)

### 20–33 хв. GROUP BY 🗣

Тепер головне. Малюй на дошці процес у три стовпці:

```
БУЛО                      ЗГРУПУВАЛИ              ПОРАХУВАЛИ
Програмування  Іваненко   ┐
Програмування  Савчук     ├─ Програмування  ──→  Програмування   3
Програмування  Лисенко    ┘
Робототехніка  Гнатюк     ┐
Робототехніка  Іваненко   ┴─ Робототехніка  ──→  Робототехніка   2
```

> `GROUP BY поле` — «склади рядки в купки за однаковим значенням цього поля,
> і для кожної купки порахуй агрегат».

```sql
SELECT class_name, COUNT(*)
FROM students
GROUP BY class_name;
```

**Правило, яке ламає всіх на початку.** Напиши на дошці й обведи:

> Усе, що стоїть у `SELECT` і **не є** агрегатною функцією,
> має бути в `GROUP BY`.

Розбери, чому. Питання класу:

```sql
SELECT class_name, last_name, COUNT(*)
FROM students
GROUP BY class_name;
```

Що тут не так? У групі «11-А» дев'ять різних прізвищ. **Яке з них база має показати?** Відповіді немає, тому вона відмовляється виконувати запит.

Це найважливіший момент уроку. Якщо клас зрозумів це питання, `GROUP BY` засвоєно.

### 33–40 хв. HAVING 🗣

Задача: показати **тільки ті класи, де більше 5 учнів**.

Перша спроба класу буде така:

```sql
SELECT class_name, COUNT(*)
FROM students
WHERE COUNT(*) > 5          -- ❌ не працює
GROUP BY class_name;
```

Розбери, чому не працює. Порядок виконання, який варто намалювати:

```
1. WHERE     ──→  відбирає РЯДКИ (до групування)
2. GROUP BY  ──→  складає купки
3. HAVING    ──→  відбирає КУПКИ (після групування)
4. ORDER BY  ──→  сортує результат
```

`WHERE` працює до того, як групи існують — він фізично не може знати `COUNT(*)`.

```sql
SELECT class_name, COUNT(*) AS [Учнів]
FROM students
GROUP BY class_name
HAVING COUNT(*) > 5;
```

Критерій вибору, простий:

| Умова стосується | Використовуй |
|---|---|
| окремого рядка (`birth_year = 2008`) | `WHERE` |
| групи в цілому (`COUNT(*) > 5`) | `HAVING` |

Обидва в одному запиті — нормально й часто потрібно.

### 40–45 хв. Заперечення в умові 🗣

Держпрограма вимагає окремо, і це справді окремий спосіб мислення.

Задача: **гуртки, у які не записався жоден учень.**

Два шляхи, обидва правильні:

```sql
-- Шлях 1: через NOT IN
SELECT name FROM clubs
WHERE id NOT IN (SELECT club_id FROM enrollments);

-- Шлях 2: через LEFT JOIN (день 8)
SELECT c.name FROM clubs c
LEFT JOIN enrollments e ON c.id = e.club_id
WHERE e.id IS NULL;
```

Скажи, що обидва дають той самий результат, і що перший часто читабельніший, а другий швидший на великих даних. Не заглиблюйся — просто покажи, що на одне питання буває кілька правильних відповідей, і це нормальна ситуація в програмуванні.

⚠ Одна пастка, про яку варто попередити: якщо в підзапиті трапиться `NULL`, `NOT IN` поводиться неочікувано й повертає порожній результат. Для сильних пар це зіркове завдання.

## Урок 2 — практика

Учні працюють за `day-09-student.md`, у своїй базі `Gurtky`.

### На що дивитись, обходячи клас

1. **Порушення правила `GROUP BY`.** Помилка `column is invalid in the select list because it is not contained in either an aggregate function or the GROUP BY clause` — довга й лякає. Але це найкорисніша помилка дня. Не давай готову відповідь, питай: «яке значення база має показати для цієї групи?»
2. **`WHERE` замість `HAVING`.** Друга за частотою. Поверни до схеми порядку виконання.
3. **Забутий `AS`.** Колонка без назви виглядає як `(No column name)`. Не помилка, але вимагай підписувати.
4. **Групування без `JOIN`.** Половина цікавих питань потребує обох: спочатку з'єднати, потім згрупувати. Це головна складність другої половини уроку.

### Тонкий момент, який варто пояснити класу вголос

Коли з'явиться перший запит «скільки учнів у кожному гуртку», зверни увагу на важливу річ: гуртки **без учнів** у результат не потраплять, якщо використовувати `JOIN`. Потрібен `LEFT JOIN`, і тоді `COUNT(e.id)` дасть 0.

```sql
SELECT c.name, COUNT(e.id) AS [Учнів]
FROM clubs c
LEFT JOIN enrollments e ON c.id = e.club_id
GROUP BY c.name;
```

⚠ І тут ще одна тонкість: `COUNT(*)` дасть **1**, а не 0, бо рядок від `LEFT JOIN` існує. Правильно `COUNT(e.id)`, бо воно рахує заповнені значення. Це прямо повертає до різниці, розібраної в теорії, і закріплює її на практиці. Варто розібрати з класом уголос.

## Що піде не так

- **Довга помилка `GROUP BY`.** Розібрано вище. Заготуй коротке формулювання: «база не знає, яке з багатьох значень показати».
- **`COUNT(*)` замість `COUNT(поле)` при `LEFT JOIN`.** Дає 1 замість 0. Дуже підступна помилка, бо запит працює й результат виглядає правдоподібно. Перевіряй очима результати.
- **Замало даних для групування.** Якщо в кожному класі по два учні, `HAVING COUNT(*) > 5` дасть порожній результат, і пара подумає, що помилилась. Скажи одразу: порожній результат — це теж результат.
- **`ORDER BY` за агрегатом.** `ORDER BY COUNT(*) DESC` працює в SQL Server, але хтось спробує `ORDER BY [Учнів]` — теж працює. Обидва варіанти правильні, не плутай їх зауваженнями.
- **Плутають `DISTINCT` і `GROUP BY`.** `SELECT DISTINCT class_name` і `SELECT class_name GROUP BY class_name` дають те саме. Скажи: коли потрібен тільки список без повторів — `DISTINCT` простіше; коли потрібні числа по групах — `GROUP BY`.
