## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–12 хв. Програма, яка не падає 🗣

Постав питання, яке всі бачили на практиці дня 15:

> Що станеться з вашою програмою, якщо SQL Server вимкнений?

Покажи на проекторі. Зупини службу або зміни пароль у `.env` на неправильний, запусти. Учні побачать вивал на пів екрана червоного тексту зі згадками файлів, про які вони ніколи не чули.

Питання класу: **що з цього зрозуміє людина, яка користується програмою?**

> Програма не має падати від передбачуваних проблем. Вона має **сказати,
> що сталося, зрозумілою мовою**.

```typescript
try {
    const pool = await sql.connect(config);
    // робота з базою
} catch (error) {
    console.log("Не вдалося підключитись до бази.");
    console.log("Перевір, чи запущений SQL Server.");
}
```

| Частина | Що означає |
|---|---|
| `try { ... }` | «спробуй виконати це» |
| `catch (error) { ... }` | «якщо не вийшло — зроби ось це» |
| `error` | об'єкт з інформацією про те, що саме сталось |

⚠ Важлива теза, яку варто сказати явно, бо вона неочевидна:

> `try/catch` не виправляє помилку. Він дає можливість **відреагувати** на неї
> замість того, щоб програма просто впала.

Три типи проблем, на які варто реагувати — розбери кожен із питанням до класу:

| Проблема | Що має зробити програма |
|---|---|
| база недоступна | сказати про це й закінчитись |
| користувач не дав аргумент | показати підказку, як користуватись |
| запит нічого не знайшов | сказати «не знайдено», а не впасти |

Останній випадок — не помилка взагалі, і це варто підкреслити: порожній результат обробляється звичайним `if`, а не `catch`.

### 12–22 хв. Запис у файл 🗣

Учні вже читали файл (у резервному плані дня 15) або бачили `fs` мимохідь. Тепер запис.

```typescript
import { writeFileSync } from "node:fs";

const report = "Звіт про гуртки\n\nВсього: 6";
writeFileSync("data/report.txt", report, "utf-8");
```

Одразу проведи паралель, вона важлива:

> Це третій спосіб зберігати результат. Ви вже знаєте два.

| Куди | Коли доречно |
|---|---|
| `console.log` | подивитись зараз |
| файл | зберегти, надіслати, відкрити в Excel |
| база | працювати з даними далі, шукати, оновлювати |

Питання класу для перевірки розуміння: у якому з трьох варіантів зберігати список учнів школи? А результат разового звіту для директора?

⚠ Одна технічна деталь, на якій вони спіткнуться: `\n` — це перехід на новий рядок. У шаблонних рядках можна просто натиснути Enter, і це працює так само.

### 22–35 хв. Що таке CLI 🗣

> **CLI** (command line interface) — інтерфейс, у якому програмою керують,
> передаючи їй команди текстом.

Учні його вже використовували весь блок: `git`, `npm`, `node` — це все CLI-програми.

Покажи на проекторі, що вони будуть робити:

```
node app/cli.ts list
node app/cli.ts find Програм
node app/cli.ts day середа
node app/cli.ts report
```

Питання класу: **звідки програма знає, яку команду виконати?**

Відповідь вони знають з дня 11: `process.argv[2]`. Це та сама механіка, тільно тепер значення означає не дані, а **команду**.

```typescript
const command = process.argv[2];

if (command === "list") {
    // ...
} else if (command === "find") {
    // ...
} else {
    console.log("Невідома команда. Доступні: list, find, day, report");
}
```

⚠ Останній `else` — обов'язковий. Скажи це прямо: **програма без підказки при неправильному вводі — недороблена програма**. Це те, що відрізняє інструмент від скрипта.

### 35–45 хв. Структура програми 🗣

Останні 10 хвилин — про архітектуру, і це прямий місток у блок 4.

Намалюй на дошці три шари:

```
   ┌─────────────────────────────────┐
   │  cli.ts    — розбирає команди   │   що хоче користувач
   ├─────────────────────────────────┤
   │  logic.ts  — обробляє дані      │   що робити з даними
   ├─────────────────────────────────┤
   │  db.ts     — говорить з базою   │   звідки дані
   └─────────────────────────────────┘
```

Ключова теза:

> Кожен шар знає **тільно про той, що під ним**. `cli.ts` не знає, звідки беруться
> дані. `db.ts` не знає, хто його викликає.

Питання класу, яке доводить користь: у блоці 3 замість командного рядка буде **веб-сторінка**. Скільки файлів доведеться переписати?

Відповідь: тільно верхній. `logic.ts` і `db.ts` залишаться як є.

Скажи прямо: **саме тому ми весь блок розбивали код на функції й файли.** Це не було вправою для вправи — у січні воно окупиться.

## Урок 2 — практика

Учні працюють за `day-16-student.md`. Це найбільше завдання блоку.

### На що дивитись, обходячи клас

1. **Хто відстав.** Файл побудований так, що робочий мінімум — команди `list` і `find`. Решта в частині «розширення». Не змушуй слабкі пари робити все — головне, щоб щось працювало.
2. **`import` між своїми файлами.** Розширення `.ts` у шляху обов'язкове: `from "./db.ts"`. Найчастіша помилка дня.
3. **Циклічні залежності.** Якщо `db.ts` імпортує з `cli.ts` — усе зламається незрозуміло. Правило одностороннє: імпорт іде тільно вниз по шарах.
4. **`try/catch` навколо всього.** Хтось обгорне всю програму одним `try` і зловить усі помилки в одне повідомлення. Працює, але некорисно. Порада: окремий `catch` для підключення, окремі `if` для порожніх результатів.

## Що піде не так

- **Забуте розширення в `import`.** `from "./db"` не працює, потрібно `from "./db.ts"`. Буде в половини класу.
- **Не хватить часу.** Найімовірніший сценарій. Тому файл учня має чіткий мінімум: дві команди. Скажи це на початку уроку вголос, інакше слабкі пари почнуть із найскладнішого й не закінчать нічого.
- **`catch` ковтає помилку.** Порожній `catch {}` або `catch { console.log("помилка") }` без деталей — і налагоджувати неможливо. Порада: у `catch` виводь і своє зрозуміле повідомлення, і `error` для себе.
- **Пароль у коді.** Хтось вирішить, що з `.env` складно, і впише пароль прямо. Перевір `git status` і сам код у кількох пар.
- **Команда `add` ламає базу.** Хтось у зірковому завданні напише `DELETE` без `WHERE`. У них є `schema.sql` і `seed.sql` — це саме той випадок, для якого вони існують. Хороша демонстрація, не сварись.
