# День 21. Flexbox. Адаптивна верстка

**Блок 3 — Веб-технології**

## Мета дня

Сторінка нормально виглядає і на комп'ютері, і на телефоні. Учні керують розташуванням елементів через Flexbox і розуміють, що таке медіа-запит.

Це другий за вдячністю день блоку: результат перевіряється поворотом телефона.

---

## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–10 хв. Проблема 🗣

Відкрий на проекторі сторінку, зроблену в дні 20, і звузь вікно браузера до ширини телефона.

Питання класу: **що не так?**

Проблем буде дві, і обидві варто назвати:

1. Картки гуртків одна під одною — на телефоні це нормально, а на широкому екрані марно витрачає місце
2. Меню, картки й таблиця не пристосовуються — таблиця виїжджає за екран

Постав факт, який знімає питання «а нащо»:

> Більшість людей заходить на сайти **з телефона**. Якщо сайт незручний на телефоні —
> це не «недоробка», це неробочий сайт.

### 10–28 хв. Flexbox 🗣

Головна частина дня. Пиши на проекторі й показуй результат після кожного рядка.

Задача: поставити картки гуртків у рядок.

```html
<div class="clubs-grid">
    <article class="club">...</article>
    <article class="club">...</article>
    <article class="club">...</article>
</div>
```

```css
.clubs-grid {
    display: flex;
    gap: 20px;
}
```

Дві головні тези, які треба сказати чітко:

> `display: flex` ставиться на **батьківський** елемент, а не на ті, що всередині.
> Батько керує тим, як розташовані діти.

> `gap` — відступ **між** дітьми. До Flexbox для цього використовували `margin`,
> і це було незручно.

Далі властивості, кожну з показом:

```css
.clubs-grid {
    display: flex;
    gap: 20px;
    flex-wrap: wrap;              /* переносити на новий рядок, якщо не вміщається */
    justify-content: space-between; /* як розподілити по горизонталі */
    align-items: stretch;          /* як розтягнути по вертикалі */
}
```

⚠ `flex-wrap: wrap` — найважливіше з цього списку. Без нього картки стискаються до нечитабельності. Покажи обидва варіанти.

І одна властивість на дитині:

```css
.club {
    flex: 1 1 250px;
}
```

Читається як: «рости, стискайся, базова ширина 250». Це рецепт «картки самі розкладаються по ширині екрана», і на цьому етапі достатньо дати його як рецепт, без розбору трьох чисел.

⚠ Не давай `flex-direction`, `align-self`, `order`, `flex-basis` окремо. Чотирьох властивостей на батькові й однієї на дитині вистачає на 90% реальних задач.

### 28–38 хв. Медіа-запит 🗣

```css
/* базові правила — для телефона */
.clubs-grid {
    display: flex;
    flex-wrap: wrap;
    gap: 20px;
}

/* якщо екран ширший за 600px — додаємо ще */
@media (min-width: 600px) {
    body {
        padding: 40px;
    }
}
```

> **Медіа-запит** — блок правил, які застосовуються лише за певної умови.
> Найчастіша умова — ширина екрана.

Скажи про порядок, це важливо:

> Спочатку пишуть стилі для **вузького** екрана, потім додають для широкого.
> Це називається mobile-first, і так роблять, бо телефон — складніший випадок:
> там менше місця, і треба вирішити, що головне.

Питання класу для перевірки: якщо телефон має ширину 400px, а в медіа-запиті `min-width: 600px` — які правила спрацюють?

### 38–45 хв. Кросбраузерність 🗣

Держпрограма вимагає, і 7 хвилин достатньо.

> **Кросбраузерність** — коли сайт працює однаково в різних браузерах.

Питання класу: чому взагалі можуть бути відмінності?

Розберіть причини:

| Причина | Приклад |
|---|---|
| різні браузери, різні розробники | Chrome, Firefox, Safari — три різні команди |
| нові можливості з'являються не одночасно | властивість уже є в Chrome, ще немає в Safari |
| старі версії живуть довго | у когось телефон 2018 року й браузер того ж року |
| у браузерів різні стилі за замовчуванням | розмір шрифту, відступи абзаців |

Скажи, що з цим роблять на практиці:

1. **Перевіряють** — у щонайменше двох браузерах
2. **Дивляться підтримку** — сайт `caniuse.com`, там для кожної властивості видно, які браузери її розуміють
3. **Скидають стилі за замовчуванням** — саме тому в CSS пишуть `* { box-sizing: border-box; }` та подібне

І одна заспокійлива теза: Flexbox і медіа-запити підтримуються всюди вже багато років. Проблеми починаються з новішими можливостями.

## Урок 2 — практика

Учні працюють за `day-21-student.md`.

### Головний інструмент дня

**F12 → Toggle device toolbar** (Ctrl + Shift + M).

Браузер показує сторінку так, як вона виглядала б на телефоні, і дає вибрати модель. Це основний спосіб перевірки, і його треба показати на проекторі.

⚠ Одразу попередь про важливу деталь: щоб емуляція працювала правильно, у `<head>` потрібен рядок

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Без нього телефон покаже сторінку зменшеною, як робочий стіл. Це найчастіша причина «я все зробив, а на телефоні не працює».

### На що дивитись, обходячи клас

1. **Немає `<meta viewport>`.** Розібрано вище. Перевіряй першим.
2. **`display: flex` поставлений на дитині.** Класична плутанина. Симптом: нічого не змінилось.
3. **Обгортка для карток не створена.** Flexbox потребує батьківського елемента. Хтось поставить `display: flex` на `<section>`, і в рядок стануть заголовок разом із картками. Наочна помилка, варто розібрати з класом, коли з'явиться.
4. **Медіа-запит без дужок або з `;`.** `@media (min-width: 600px) { }` — дужки й фігурні дужки обов'язкові.
5. **Таблиця на телефоні.** Вона все одно виїжджає. Рішення в завданні є (`overflow-x: auto`), але воно неочевидне.

## Що піде не так

- **`<meta viewport>`.** Найважливіше. Скажи на початку уроку.
- **Flexbox «не працює».** У 90% випадків — поставлений не на батька. Питання, яке допомагає: «а хто тут батько?»
- **Картки різної висоти.** Виглядає неохайно. Рішення: `align-items: stretch` (за замовчуванням) плюс `display: flex; flex-direction: column` на самій картці. Це є в зірковому, але хтось спитає раніше.
- **Емуляція телефона показує не те.** Треба перезавантажити сторінку після включення емуляції. Дрібниця, але збиває.
- **Затягування.** Підбір ширин може з'їсти весь урок. Оголоси, що спочатку — обов'язкові частини.
- **Немає чим перевірити в другому браузері.** Якщо на машинах лише Chrome, зіркове завдання про кросбраузерність не спрацює. Тоді достатньо показати `caniuse.com` на проекторі... якщо є інтернет. Якщо ні — залишається розмова.
