## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–15 хв. Умова: програма вирішує 🗣

Поверни задачу з дня 11, яку SQL не міг розв'язати:

> Записати учня в гурток, **але тільько якщо** там є вільні місця.

Пиши на проекторі поступово, питаючи клас на кожному кроці.

```typescript
const maxStudents = 14;
const enrolled = 9;

if (enrolled < maxStudents) {
    console.log("Місця є, записуємо");
} else {
    console.log("Гурток заповнений");
}
```

Розбір частин:

| Частина | Що означає |
|---|---|
| `if (умова)` | «якщо умова правдива» |
| `{ ... }` | що робити, якщо правдива |
| `else { ... }` | що робити, якщо ні |

**Головна вправа цієї частини.** Змінюй `enrolled` на проекторі й **питай клас, що виведеться, ДО того як запустиш**. По черзі: 9, 14, 15, 0.

Випадок `enrolled = 14` — найцікавіший. `14 < 14` — це неправда, тому «заповнений». Хтось із класу помилиться, і це корисно: розмова про `<` проти `<=` виникне сама.

Оператори порівняння на дошці:

| | |
|---|---|
| `>` `<` `>=` `<=` | більше, менше, не менше, не більше |
| `===` | **дорівнює** |
| `!==` | не дорівнює |

⚠ **Три знаки рівності.** Це найчастіша помилка в тижні. `=` кладе значення в змінну, `===` порівнює. Скажи це двічі й напиши на дошці.

⚠ Проведи паралель із SQL, вона допомагає:

| SQL | TypeScript |
|---|---|
| `WHERE enrolled < max_students` | `if (enrolled < maxStudents)` |
| `AND` | `&&` |
| `OR` \| | `\|\|` |
| `NOT` | `!` |

Логіка та сама, синтаксис інший.

### 15–25 хв. Кілька умов 🗣

```typescript
if (enrolled === 0) {
    console.log("Ще ніхто не записався");
} else if (enrolled < maxStudents) {
    console.log(`Вільних місць: ${maxStudents - enrolled}`);
} else {
    console.log("Гурток заповнений");
}
```

Ключова теза: **перевірка йде згори вниз і зупиняється на першій правдивій умові**.

Питання класу для перевірки розуміння: що буде, якщо в цьому коді поставити гілки в іншому порядку — спочатку `enrolled < maxStudents`, потім `enrolled === 0`? (Відповідь: гілка з нулем ніколи не виконається, бо `0 < 14` теж правда.)

Це важливий момент. Порядок умов має значення, і це не очевидно.

### 25–40 хв. Цикл: програма повторює 🗣

Постав задачу, у якій ручна робота очевидно безглузда:

> Вивести список номерів кабінетів з 201 по 215.

Питання класу: скільки рядків `console.log` треба написати? А якщо з 201 по 350?

```typescript
for (let i = 201; i <= 215; i++) {
    console.log(`Кабінет ${i}`);
}
```

Розбір трьох частин у дужках — це головне, що треба зрозуміти:

| Частина | Що означає | Коли виконується |
|---|---|---|
| `let i = 201` | з чого почати | один раз, на початку |
| `i <= 215` | доки продовжувати | перед кожним повторенням |
| `i++` | що робити після кроку | після кожного повторення |

**Трасування на проекторі.** Це найкорисніші 8 хвилин дня. Візьми короткий цикл і розпиши на дошці таблицю виконання:

```typescript
for (let i = 1; i <= 3; i++) {
    console.log(i);
}
```

| Крок | `i` | `i <= 3`? | Що виведе | Далі |
|---|---|---|---|---|
| 1 | 1 | так | `1` | `i` стає 2 |
| 2 | 2 | так | `2` | `i` стає 3 |
| 3 | 3 | так | `3` | `i` стає 4 |
| 4 | 4 | **ні** | — | цикл закінчився |

Заповнюй таблицю разом із класом, питаючи на кожному рядку. Потім запусти й порівняй.

Далі зроби те саме з `i < 3` замість `i <= 3` і питай, що зміниться. Різниця в один символ — різниця в результаті.

### 40–45 хв. Умова всередині циклу 🗣

Дві конструкції разом — і вже видно щось схоже на справжню програму.

```typescript
for (let i = 1; i <= 10; i++) {
    if (i % 2 === 0) {
        console.log(`${i} — парне`);
    }
}
```

Нагадай, що `%` — це остача від ділення (вони бачили в зіркових завданнях дня 11).

Скажи, що на практиці вони робитимуть саме це: **перебирати список і щось перевіряти на кожному елементі**. У дні 13 замість чисел буде список учнів.

## Урок 2 — практика

Учні працюють за `day-12-student.md`.

### На що дивитись, обходячи клас

1. **`=` замість `===`.** Найчастіша помилка дня. У TypeScript це часто дасть підкреслення в редакторі, але не завжди. Дивись очима.
2. **Нескінченний цикл.** Хтось напише `i--` замість `i++` або забуде змінювати `i`. Термінал зависне й буде друкувати вічно. Рішення: **Ctrl + C**. Скажи це заздалегідь, інакше буде паніка.
3. **Границі циклу.** `<` проти `<=`, початок з 0 чи з 1. Головне джерело «на один більше / на один менше». Порада: після кожного циклу питати «скільки рядків має вийти?» **до** запуску.
4. **Фігурні дужки.** Забута закриваюча — і файл не виконується взагалі. VS Code підсвічує пару дужок, покажи це.

### Що показати на проекторі перед початком (2 хвилини)

Запусти нескінченний цикл навмисно:

```typescript
for (let i = 1; i <= 10; i--) {
    console.log(i);
}
```

Хай побачать, що терміналом можна керувати: **Ctrl + C** зупиняє. Це прибирає страх «я щось зламав».

## Що піде не так

- **Нескінченний цикл.** Розібрано вище. Обов'язково попередь про Ctrl + C.
- **Помилка «на одиницю».** Класична й неминуча. Не виправляй за них — питай: «скільки рядків очікував? скільки вийшло? де зайвий?»
- **Плутають `&&` і `||`.** Порада: читати вголос. `&&` — «і те, і те». `||` — «або одне, або інше». Читання вголос вирішує 80% таких помилок.
- **Забувають, що `i` існує тільки всередині циклу.** Спроба використати `i` після циклу дасть помилку. Не заглиблюйся в область видимості — скажи просто: «`i` живе в дужках циклу».
- **Копіюють код і не змінюють імена змінних.** Дві змінні `i` в одному файлі — помилка. Дивись очима.
- **Занадто швидкий темп у сильних пар.** У класі буде пара, яка зробить усе за 20 хвилин. Зіркових завдань у файлі учня п'ять — має вистачити.
