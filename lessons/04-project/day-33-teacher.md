| Варіант | Коли | Що робити |

## Варіант A: догнати

Якщо клас відстав, найкорисніше — не пробігти пропущене, а закрити **прогалини, які ламають наступне**.

Пріоритет, за спаданням важливості:

| День | Чому критично |
|---|---|
| 7 (зв'язок M:N) | без нього не працює нічого далі |
| 24 (сервер і API) | без нього немає системи, тільно окремі частини |
| 6 (`CREATE TABLE`) | без своєї бази проект не існує |
| 25 (форми) | єдине місце, де система приймає дані |
| 31 (відтворення з нуля) | без цього проект живе на одному комп'ютері |

Решту можна пропустити без наслідків для цілісності продукту.

## Варіант C: усе вкладається

Тоді день будується так.

### Урок 1 — підсумок року (без комп'ютерів)

**0–15 хв. Що зробили.** Виведи на проектор схему архітектури з дня 31 і пройдись по ній:

```
   БРАУЗЕР                СЕРВЕР                        БАЗА
   ┌──────────────┐      ┌─────────────────────┐      ┌────────────┐
   │ index.html   │      │ server.ts  маршрути │      │ teachers   │
   │ style.css    │◄────►│ logic.ts   логіка   │◄────►│ clubs      │
   │ app.js       │ HTTP │ models.ts  класи    │ SQL  │ students   │
   │              │ JSON │ db.ts      доступ   │      │ enrollments│
   └──────────────┘      └─────────────────────┘      └────────────┘
      день 18–23             день 11–16, 24–29          день 3–10
```

Скажи конкретно, а не загально:

> База даних із чотирьох таблиць і трьох типів зв'язків. Серверна програма
> на TypeScript із класами й обробкою помилок. Веб-інтерфейс з адаптивною
> версткою й доступністю. API, форми з валідацією на двох рівнях.
> Документація вимог, три UML-діаграми. Робота з Git, гілками, конфліктами.
>
> Усе це — з нуля, за один навчальний рік.

Клас не усвідомлює обсягу: вони бачили його по одному уроку за раз.

**15–30 хв. Що далі, якщо цікаво.** Найкорисніша частина для тих, хто піде в ІТ.

Чого вони **не** вчили, і що варто знати:

| Тема | Чому пропустили | Де брати |
|---|---|---|
| Авторизація й права доступу | не хватило часу; це наступний крок їхнього проекту | будь-який курс з веб-розробки |
| Тестування (автотести) | окремий великий блок | Jest, Vitest |
| Алгоритми й складність | зачіпали побіжно; потрібно для співбесід | LeetCode, Codeforces |
| Docker і деплой | вимагає адміністрування | після базового рівня |
| React серйозно | тільно торкнулись у дні 26 | офіційна документація React |

Скажи головне про самонавчання:

> Ви вже вмієте головне: читати помилку, шукати причину, розбивати задачу
> на частини. Технології змінюються, це — ні.

**30–45 хв. Питання.** Відкритий формат. Учні за рік накопичили питання, на які не було часу.

Заготовки, якщо клас молчить:
- як влаштована робота програміста насправді
- скільно платять і за що
- чи потрібна вища освіта
- як обирають технології в реальних проектах
- що спитають на першій співбесіді

## Що зробити після курсу

### Архівувати роботи

Репозиторії залишаються в організації GitHub і не зникнуть. Але:

- **токени протермінуються** — і це добре, доступ закриється сам
- наступному класу потрібні **нові репозиторії**, не ці

Найпростіше: залишити як є, наступного року створити `pc-01-2027` і далі. Історія попереднього класу збережеться.

### Якщо хтось хоче забрати свою роботу

Учень, який зареєстрував акаунт GitHub, може отримати копію свого репо: додай його як колаборатора, або зроби для нього форк. Це варте того — річна історія комітів реальний артефакт для вступу.

Скажи про це на останньому уроці. Знайдеться двоє-троє, кому це справді потрібно.

### Що виправити в курсі до наступного року

Заведи файл і записуй по ходу — до кінця року деталі забудуться. Що варто зафіксувати:

- на якому дні клас реально відстав
- чи вдалась автентифікація SQL Server у дні 15 (це головний технічний ризик)
- чи працював npm і чи дійшли до React у дні 26
- які помилки повторювались у більшості (додати їх у `reference/errors.md`)
- які завдання виявились задовгими або закороткими
- чи вкладались захисти в дні 32 у час
