## Урок 1 — теорія (з проектором, комп'ютери учнів закриті)

### 0–10 хв. Розділення структуру й оформлення 🗣

Поверни до дня 18, де прозвучало питання «а де кольори».

Постав задачу: **у вас двадцять сторінок, і директор просить змінити колір заголовків.**

Розбери два варіанти на дошці:

| Підхід | Скільки правити |
|---|---|
| колір вписаний у кожен тег | двадцять сторінок × кожен заголовок |
| колір описаний в одному місці | один рядок |

> **CSS** описує, **як виглядає** те, що описано в HTML.
> HTML — структура. CSS — оформлення. Це різні файли.

Це та сама ідея, що функція в дні 14: винести спільне в одне місце. Назви паралель — вона точна й допомагає.

### 10–22 хв. Селектор: до чого застосувати 🗣

Пиши на проекторі, показуй результат після кожного кроку.

```css
h1 {
    color: darkblue;
}
```

| Частина | Назва |
|---|---|
| `h1` | **селектор** — до чого застосувати |
| `color` | **властивість** — що змінюємо |
| `darkblue` | **значення** |
| `color: darkblue;` | **оголошення** |

Три види селекторів, більше сьогодні не потрібно:

```css
h1        { }   /* усі теги h1 */
.club     { }   /* усі елементи з class="club" */
#header   { }   /* елемент з id="header" — один на сторінку */
```

⚠ Скажи одразу правило, яке рятує від плутанини:

> `class` — для **групи** однакових елементів. Може повторюватись.
> `id` — для **одного** конкретного елемента. Унікальний на сторінці.
> На практиці 95% селекторів — це класи.

Комбінації, які знадобляться в практиці:

```css
article h3     { }   /* h3 всередині article */
.club, .event  { }   /* і .club, і .event */
```

### 22–35 хв. Блокова модель 🗣

Це головна частина дня. Без неї учні три уроки не розумітимуть, чому елементи не стають туди, куди треба.

Малюй на дошці й одночасно показуй у F12 → Elements → Computed (там ця схема є вбудована в браузер):

```
   ┌─────────────────────────────────────┐
   │            margin                   │  ← зовні, між елементами
   │   ┌─────────────────────────────┐   │
   │   │         border              │   │  ← рамка
   │   │   ┌─────────────────────┐   │   │
   │   │   │      padding        │   │   │  ← всередині, до вмісту
   │   │   │   ┌─────────────┐   │   │   │
   │   │   │   │   вміст     │   │   │   │
   │   │   │   └─────────────┘   │   │   │
   │   │   └─────────────────────┘   │   │
   │   └─────────────────────────────┘   │
   └─────────────────────────────────────┘
```

Формулювання, яке працює:

| | |
|---|---|
| `padding` | відступ **всередині** рамки — між рамкою й текстом |
| `border` | сама рамка |
| `margin` | відступ **зовні** — між цим елементом та іншими |

⚠ **Показ, який варто зробити обов'язково.** У F12 наведи мишку на елемент і покажи, як браузер розфарбовує margin і padding різними кольорами. Це знімає 80% майбутніх питань.

Тепер про пастку, яка ловить усіх:

```css
.card {
    width: 300px;
    padding: 20px;
    border: 2px solid gray;
}
```

Питання класу: **яка реальна ширина цього блоку?**

Відповідь за замовчуванням — 344 пікселі, бо `width` стосується тільно вмісту. Це неочікувано й ламає верстку.

Рішення, яке ставлять у кожному сучасному проекті:

```css
* {
    box-sizing: border-box;
}
```

> Тепер `width: 300px` означає **300 разом з рамкою й відступами**. Так інтуїтивніше.

Скажи прямо: цей рядок пишуть на початку майже кожного CSS-файлу, і зараз ми теж напишемо.

### 35–45 хв. Блокові та рядкові елементи 🗣

Коротке, але необхідне.

```html
<p>Це абзац</p>
<p>Це другий абзац</p>

<span>Це</span> <span>рядкові</span> <span>елементи</span>
```

| Тип | Поведінка | Приклади |
|---|---|---|
| **блокові** | займають усю ширину, стають один під одним | `div`, `p`, `h1`, `article`, `section` |
| **рядкові** | займають лише свою ширину, стають у рядок | `span`, `a`, `strong`, `em` |

⚠ Наслідок, який варто назвати: `width` і `height` **не працюють** на рядкових елементах. Хтось на це наткнеться, і причина буде незрозуміла.

Це і є мостик у день 21: щоб керувати розташуванням серйозно, потрібен Flexbox.

## Урок 2 — практика

Учні працюють за `day-20-student.md`.

### Технічний момент

CSS підключається **окремим файлом**: `web/style.css` через `<link>` у `<head>`.

⚠ Не дозволяй `style="..."` прямо в тегах і не дозволяй `<style>` усередині HTML. Причина не в чистоті, а в тому, що весь урок побудований на ідеї розділення. Якщо вони почнуть з інлайн-стилів, ідея не дійде.

### На що дивитись, обходячи клас

1. **Забутий `<link>`.** Симптом: CSS написаний, а нічого не змінилось. Найчастіша проблема першої третини уроку. Перевіряй `href` по літерах.
2. **Крапка перед класом.** У HTML — `class="club"`, у CSS — `.club`. Без точки селектор шукає **тег** з назвою `club`, якого не існує. Помилки не буде, просто нічого не спрацює.
3. **Забута крапка з комою** в кінці оголошення. Ламає наступне правило, а не поточне — тому шукають не там.
4. **Кольори словами.** `red`, `blue`, `darkblue` працюють, і на цьому етапі цього достатньо. Не вимагай hex.

### Що показати на проекторі перед початком (3 хвилини)

Відкрий F12 → Elements, вибери елемент, і в панелі Styles **зміни значення прямо там**. Покажи, що можна експериментувати без правки файлу, і що зміни зникнуть після F5.

Це головний робочий інструмент верстальника, і вони будуть ним користуватись весь блок.

## Що піде не так

- **Забутий `<link>`.** Розібрано вище.
- **«Не працює», а насправді не збережено.** Той самий цикл, що весь курс: Ctrl + S → F5. Нагадай.
- **Правило перекриває інше.** Два правила для того самого елемента, спрацьовує останнє або більш конкретне. Не читай лекцію про специфічність — покажи F12 → Styles, там перекреслені властивості видно наочно.
- **`margin` між блоками менший за очікуваний.** Сусідні вертикальні `margin` злипаються в один. Це реальна особливість CSS, і вона дивує. Скажи фактом, не заглиблюйся.
- **Хтось зробить сторінку рожевою з жовтим текстом.** Не сварись — це нормальний етап. Але зіркове завдання про контраст у Lighthouse поверне їх до реальності.
- **Час.** CSS затягує: можна півгодини підбирати відтінок. Оголоси, що спочатку треба зробити всі обов'язкові частини, а красу — потім.
