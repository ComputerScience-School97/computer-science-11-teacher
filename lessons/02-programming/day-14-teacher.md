### 12–25 хв. Функція 🗣

```typescript
function printClubsByDay(day: string) {
    console.log(`--- Гуртки в ${day} ---`);
    for (const club of clubs) {
        if (club.weekday === day) {
            console.log(club.name);
        }
    }
}

printClubsByDay("середа");
printClubsByDay("четвер");
printClubsByDay("понеділок");
```

Розбір частин:

| Частина | Що означає |
|---|---|
| `function` | оголошуємо функцію |
| `printClubsByDay` | ім'я, за яким її викликають |
| `(day: string)` | **параметр**: значення, яке приходить зовні, і його тип |
| `{ ... }` | тіло — що функція робить |
| `printClubsByDay("середа")` | **виклик**: запуск функції з конкретним значенням |

Головна ідея, яку варто повторити: **функція описується один раз, викликається багато**.

⚠ Проведи паралель, яка допоможе: `day` усередині функції — це те саме, що `process.argv[2]` у дні 11. Значення приходить зовні, і функція працює по-різному залежно від нього.

### 25–37 хв. Функція, яка повертає значення 🗣

Це важливіший тип функції, і різницю треба показати явно.

```typescript
function countFreePlaces(max: number, enrolled: number): number {
    return max - enrolled;
}

const free = countFreePlaces(14, 9);
console.log(`Вільних місць: ${free}`);
```

| Частина | Що означає |
|---|---|
| `(max: number, enrolled: number)` | два параметри, обидва числа |
| `: number` після дужок | **тип того, що функція віддає** |
| `return` | «віддай це назовні й закінчи роботу» |

Різниця, яку варто написати на дошці двома рядками:

| | Що робить |
|---|---|
| функція **без** `return` | щось робить (виводить, зберігає) |
| функція **з** `return` | обчислює й **віддає результат**, а що з ним робити — вирішує той, хто викликав |

Друга гнучкіша. Приклад на проекторі:

```typescript
const free = countFreePlaces(14, 9);

console.log(free);                      // вивести
if (free > 0) { /* записати учня */ }   // ухвалити рішення
const total = free + countFreePlaces(10, 8);  // порахувати далі
```

Одна функція — три різні застосування. Це і є користь від `return`.

⚠ Покажи, чому тип повернення корисний:

```typescript
function countFreePlaces(max: number, enrolled: number): number {
    return "багато";     // ❌ VS Code підкреслює
}
```

### 37–45 хв. Функція, що повертає список 🗣

Підготовка до практики й до дня 15.

```typescript
function findClubsByDay(day: string): Club[] {
    const result: Club[] = [];
    for (const club of clubs) {
        if (club.weekday === day) {
            result.push(club);
        }
    }
    return result;
}

const wednesday = findClubsByDay("середа");
console.log(`Знайдено: ${wednesday.length}`);
for (const club of wednesday) {
    console.log(club.name);
}
```

Нове тут одне: `result.push(club)` — «додай елемент у кінець списку». Пояснення в одне речення, не більше.

Скажи, куди це веде: у дні 15 така сама функція **питатиме базу** замість того, щоб перебирати масив. Усе, що зовні від функції, не зміниться взагалі. Це і є сенс розбиття на функції — можна замінити внутрішній механізм, не ламаючи решту програми.

## Урок 2 — практика

Учні працюють за `day-14-student.md`. Суть — рефакторинг: беруть свій код із дня 13 і переписують у функції.

### На що дивитись, обходячи клас

1. **Виклик без дужок.** `printClubs` замість `printClubs()`. Помилки не буде — просто нічого не станеться. Підступно.
2. **Забутий `return`.** Функція з типом повернення, але без `return`, дасть підкреслення. З типом `void` — не дасть, і результат буде `undefined`.
3. **Плутають виведення і повернення.** `console.log` усередині функції замість `return`. Працює, але функцію не можна перевикористати. Це головна концептуальна складність дня.
4. **Порядок у файлі.** Функцію можна викликати до її оголошення (це працює), але вимагай спочатку оголошення, потім виклики — читабельніше.

### Що показати на проекторі перед початком (2 хвилини)

Функцію з `return` і функцію без. Виклич обидві, покажи, що перша дає значення, яке можна покласти в змінну, а друга — `undefined`. Це та різниця, яку найважче зрозуміти зі слів.

## Що піде не так

- **«Навіщо це, якщо працювало й так».** Найчастіше питання дня, і воно справедливе — на трьох рядках функції справді зайві. Не відповідай абстрактно. Скажи: у дні 16 у вас буде програма на 150 рядків, і без функцій ви в ній потонете. І покажи це на проекторі: код дня 13 у файлі учня займає 80 рядків, після рефакторингу — 40.
- **Забуті дужки при виклику.** Розібрано вище. Дивись очима.
- **Функція повертає `undefined`.** Забутий `return` або `console.log` замість нього.
- **Занадто багато параметрів.** Хтось зробить функцію з шістьма параметрами й переплутає порядок. Скажи правило: більше трьох параметрів — знак, що функція робить занадто багато. Не заглиблюйся.
- **Копіюють функцію й забувають перейменувати.** Дві функції з однаковим іменем — помилка. VS Code підкреслить.
