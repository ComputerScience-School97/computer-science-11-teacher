## Урок 1 — теорія (без комп'ютерів)

### 0–10 хв. Три слова 🗣

Малюй на дошці таблицю й підписуй її частини:

```
                    А Т Р И Б У Т И
                 ┌──────┬──────────┬─────────┐
                 │  id  │   name   │  room   │
                 ├──────┼──────────┼─────────┤
   ЗАПИС  ──────>│  1   │ Програм. │   215   │
                 │  2   │ Робото.  │   108   │
                 │  3   │ Газета   │   302   │
                 └──────┴──────────┴─────────┘
                  СУТНІСТЬ: Гурток (таблиця clubs)
```

| Термін | Простими словами | У таблиці |
|---|---|---|
| **Сутність** | тип речі, про яку зберігаємо дані | вся таблиця |
| **Атрибут** | одна характеристика цієї речі | колонка / поле |
| **Запис** | один конкретний екземпляр | рядок |

Ключова теза, яку варто повторити кілька разів за блок:

> Сутність — це **тип**, запис — це **екземпляр**. «Гурток» — сутність. «Гурток програмування в 215 кабінеті» — запис.

Швидка вправа усно: назви сутність, атрибути й один запис для: книги в бібліотеці, товару в магазині, футбольного матчу.

### 10–25 хв. Навіщо потрібен ключ 🗣

Знову почни з проблеми. Напиши на дошці таблицю без `id`:

| Прізвище | Ім'я | Клас |
|---|---|---|
| Іваненко | Тарас | 11-А |
| Іваненко | Тарас | 11-А |
| Савчук | Марія | 11-А |

Питання: **це один Тарас Іваненко чи двоє?**

Ситуація реальна: у школі бувають однофамільці й повні тезки. Розвивай:

- Хочемо видалити одного Тараса. Як сказати системі, якого саме?
- Тарас перейшов у 11-Б. Який рядок правити?
- Тарас записався в гурток. Як позначити, що це саме він?

Вивід, до якого клас доходить сам:

> **Первинний ключ** — атрибут (або набір атрибутів), який однозначно визначає запис. Двох записів з однаковим ключем бути не може.

### 25–35 хв. Який атрибут брати за ключ 🗣

Розбери варіанти для таблиці учнів. Це важлива інженерна розмова, не формальність.

| Кандидат | Проблема |
|---|---|
| Прізвище | однофамільці |
| Прізвище + ім'я | тезки бувають |
| Прізвище + ім'я + дата народження | майже унікально, але громіздко; а якщо учень змінить прізвище? |
| Номер телефону | може змінитись, може не бути |
| **Окреме числове поле `id`** | ✅ ніколи не змінюється, завжди є, коротке |

Терміни:
- **природний ключ** — узятий з реальних даних (номер паспорта, ІНН)
- **штучний (сурогатний) ключ** — вигаданий номер, який нічого не означає, крім «це запис №7»

Скажи прямо: **на практиці майже завжди беруть штучний `id`**. Причина головна — природні дані змінюються, а ключ змінюватись не має.

### 35–45 хв. Правила відбору 🗣

Підготовка до практики. Напиши на дошці й розбери три конструкції **без комп'ютера**:

```sql
SELECT ... FROM ... WHERE умова;
SELECT ... FROM ... ORDER BY поле;
SELECT TOP число ... FROM ...;
```

Порівняння операторів на дошці: `=`, `<>` (або `!=`), `>`, `<`, `>=`, `<=`, `AND`, `OR`, `NOT`, `LIKE`.

⚠ Головна пастка: **текст у лапках, числа без лапок**.
```sql
WHERE class_name = N'11-А'   -- правильно
WHERE class_name = '11-А'    -- кирилиця зіпсується
WHERE class_name = 11-А      -- помилка
WHERE birth_year = 2008      -- правильно (число без лапок)
```

**Розбір на дошці (5 хвилин).** Даєш задачу словами, клас диктує запит, ти пишеш на дошці. Три задачі:

1. Гуртки, що проходять у понеділок
2. Учні 2008 року народження
3. Гуртки з місткістю більше 12

Питай не «як буде запит», а покроково: «звідки беремо?» → `FROM clubs`. «Що показуємо?» → `SELECT name`. «Яка умова?» → `WHERE weekday = ...`. Так вони бачать, що запит складається з відповідей на прості питання, а не вигадується цілком.

## Урок 2 — практика

### Крок 0. Ритуал ⌨


### Крок 1. Розібрати разом 3 приклади ⌨

Новий аркуш у SSMS (**Ctrl + N**), одразу **Save As** у `sql/day04.sql`. Ти виводиш на проектор, вони набирають і виконують:

```sql
-- Гуртки в понеділок
SELECT name, room, start_time
FROM clubs
WHERE weekday = 'понеділок';

-- Учні 11-А, за алфавітом
SELECT last_name, first_name
FROM students
WHERE class_name = '11-А'
ORDER BY last_name;

-- Три найбільші гуртки за місткістю
SELECT TOP 3 name, max_students
FROM clubs
ORDER BY max_students DESC;
```

Розбери вголос порядок: **спочатку відбір (`WHERE`), потім сортування (`ORDER BY`), потім обрізання (`TOP`)**. Це саме той порядок, у якому працює база. ⚠ Але в SQL Server `TOP` пишеться **на початку**, одразу після `SELECT`, хоч виконується останнім. Це неочевидно, назви це явно.

### Крок 2. Заготовки з пропусками ⌨

Це формат, який працює для нульового класу краще, ніж «напишіть запит». Дай файл із пропусками:

```sql
-- 1. Учні, які народились після 2008 року
SELECT last_name, first_name, birth_year
FROM students
WHERE birth_year ____ 2008;

-- 2. Гуртки, які НЕ в 215 кабінеті
SELECT name, room
FROM clubs
WHERE room ____ '215';

-- 3. Гуртки місткістю від 10 до 16 включно
SELECT name, max_students
FROM clubs
WHERE max_students >= ____ AND max_students <= ____;

-- 4. Учні 11-А та 11-Б
SELECT last_name, class_name
FROM students
WHERE class_name = '11-А' ____ class_name = '11-Б';

-- 5. Гуртки, у назві яких є слово "клуб"
SELECT name
FROM clubs
WHERE name LIKE '%____%';

-- 6. П'ять останніх учнів за алфавітом
SELECT TOP ____ last_name
FROM students
ORDER BY last_name ____;
```

### Крок 3. Самостійні запити ⌨

Тепер без пропусків. Візьми три питання **зі списку, який клас склав на дні 3** (крок 6 практики) — з тих, що діти самі придумали. Це різко змінює мотивацію порівняно з вигаданими задачами.

Плюс обов'язково:

7. Гуртки, що починаються о 15:00
8. Учні, чиє прізвище починається на «К»

### Крок 4. Пастка з ключем ⌨

Покажи це особисто, воно закріплює теорію дня:

```sql
SELECT * FROM students WHERE id = 7;
SELECT * FROM students WHERE last_name = 'Романюк';
```

Перший запит **завжди** дає рівно один рядок або нуль. Другий може дати кілька. Питання класу: чому? Відповідь — бо `id` первинний ключ, а прізвище ні.

## Що піде не так

- **Кириличні лапки.** Якщо копіюють з Word або з чату, `'11-А'` може стати `’11-А’`, і запит не працює. Симптом — незрозуміла syntax error. Перевіряй першим.
- **`'11-А'` з латинською A.** Українська `А` і латинська `A` виглядають однаково. Це найбільш нервова помилка блоку. Порада: нехай копіюють значення з результату `SELECT DISTINCT class_name`.
- **`WHERE name = 'клуб'` замість `LIKE`.** Очікують, що знайде за частиною слова. Хороший момент пояснити різницю точної рівності й шаблону.
- **Плутають `ORDER BY` і `GROUP BY`.** Другого ще не було, але хтось побачить у інтернеті. Скажи: групування буде в дні 9, зараз тільки сортування.
- **Зберігають аркуш не в папку проекту.** Друга поспіль причина «нічого не зарахувалось». Перевір `git status` у кількох пар перед кінцем уроку, не після.
- **F5 виконує весь аркуш.** До кінця дня 4 у файлі буде 16 запитів, і хтось запустить усі одразу, отримає 16 вкладок результату й розгубиться. Нагадай про виділення на початку уроку.
- **Пишуть `LIMIT` замість `TOP`.** Так у більшості прикладів в інтернеті. Поясни різницю один раз і повісь шпаргалку.
