## Урок 1 — теорія (без комп'ютерів)

### 0–12 хв. Навіщо програма, якщо є база 🗣

Це головне питання блоку, і його варто поставити прямо. Клас щойно провів вісім уроків, навчившись діставати з бази будь-що. Логічне питання: **що ще потрібно?**

Постав чотири задачі й питай, чи можна їх розв'язати одним SQL-запитом:

| Задача | SQL справиться? |
|---|---|
| «Скільки учнів у гуртку "Програмування"?» | ✅ так, один запит |
| «Записати учня в гурток, але **тільки якщо** там є вільні місця» | ❌ треба спочатку перевірити, потім вирішити |
| «Щопонеділка о 8:00 надсилати вчителям список їхніх гуртків» | ❌ SQL не вміє «щопонеділка» |
| «Показати учневі кнопку "Записатись"» | ❌ SQL не малює інтерфейси |

Виведення, яке варто написати на дошці:

> **База відповідає на питання. Програма ухвалює рішення й діє.**

Розверни на прикладі другої задачі. Що треба зробити:

1. запитати в базі, скільки вже записано
2. запитати `max_students`
3. **порівняти** ці числа
4. **якщо** місця є — виконати `INSERT`
5. **інакше** — сказати, що місць немає

Пункти 3–5 SQL не робить. Це і є програмування: послідовність, умова, рішення.

### 12–22 хв. Що таке Node.js 🗣

Не починай з «середовища виконання JavaScript» — це нічого не пояснює.

> **JavaScript** — мова програмування. Її придумали, щоб робити сторінки в браузері живими.
> **Node.js** — програма, яка виконує JavaScript **не в браузері**, а прямо на комп'ютері.

Аналогія, яка працює: SQL Server виконує SQL. Node виконує JavaScript. Обидва — просто програми, які читають текст і роблять те, що там написано.

Чому нам це важливо: одна мова і на сервері, і в браузері. У блоці 3 вони писатимуть сайт, і мова буде та сама. Це реальна економія, і варто сказати про неї вголос.

### 22–35 хв. Змінні та типи 🗣

Розбір на дошці, з проектором. Ти пишеш код, клас відповідає, що буде.

**Змінна — це підписана коробка для значення.**

```typescript
let clubName = "Програмування";
let maxStudents = 14;
let isActive = true;
```

Три базові типи:

| Тип | Що це | Приклад |
|---|---|---|
| `string` | текст | `"Програмування"` |
| `number` | число (і ціле, і дробове) | `14`, `3.5` |
| `boolean` | так / ні | `true`, `false` |

⚠ Одразу проведи паралель із базою, це важливо:

| SQL | TypeScript |
|---|---|
| `NVARCHAR(100)` | `string` |
| `INT`, `DECIMAL` | `number` |
| `BIT` | `boolean` |

Скажи: типи — не нова ідея. Вони їх уже вибирали в дні 6, коли писали `CREATE TABLE`.

**`let` і `const`:**

```typescript
let count = 5;
count = 6;          // ✅ можна

const schoolName = "Ліцей №1";
schoolName = "Інший";   // ❌ помилка
```

Правило, яке варто вимагати: **за замовчуванням `const`**. `let` — тільки коли значення справді має змінюватись. Це рятує від помилок і читається краще.

### 35–45 хв. Навіщо TypeScript 🗣

Тут варто бути переконливим, бо синтаксис типів здасться зайвою роботою.

Покажи на проекторі звичайний JavaScript:

```javascript
let maxStudents = 14;
maxStudents = "чотирнадцять";   // помилки немає!
```

Питання класу: а що станеться, коли ми спробуємо порахувати `maxStudents - 3`?

Тепер те саме з типом:

```typescript
let maxStudents: number = 14;
maxStudents = "чотирнадцять";   // ❌ VS Code підкреслює червоним ОДРАЗУ
```

> **TypeScript** — це JavaScript, у якому можна вказувати типи.
> Помилка видна **до запуску**, а не через пів години.

Покажи на проекторі другу перевагу, яка для них цінніша за першу: **автодоповнення**. Набери `clubName.` і покажи список того, що можна зробити з рядком. Це те, чим вони користуватимуться щодня.

Дозування, яке варто сказати вголос: сьогодні тільки `string`, `number`, `boolean`. Нічого складнішого до дня 13.

## Урок 2 — практика

Учні працюють за `day-11-student.md`.

### ⚠ Пастка з кодуванням — попередь до початку

У стандартному терміналі Windows (`cmd`) українські літери з `console.log` виводяться сміттям. Причина — кодова сторінка.

**Рішення: працювати у вбудованому терміналі VS Code** (**Ctrl + `**), він за замовчуванням UTF-8. Це прописано у файлі учня, але скажи вголос — інакше половина класу вирішить, що зламала Node.

Якщо хтось таки в `cmd`, врятує `chcp 65001` перед запуском.

### tsconfig.json

У курсовому репо лежить `project/tsconfig.json`. Учні копіюють його в корінь свого проекту на дні 11.

Він не потрібен для запуску — Node виконує `.ts` без нього. Потрібен, щоб VS Code включив `strict` і перевіряв код суворіше. Свідомо вимкнено `noUncheckedIndexedAccess`: з ним кожне `arr[i]` вимагало б перевірки на `undefined`, і клас потонув би в помилках уже на дні 13.

### На що дивитись, обходячи клас

1. **Термінал у правильній папці.** `node app/hello.ts` працює тільки з кореня проекту. Половина спроб «нічого не працює» — це не той `cd`.
2. **Розширення файлу.** `.ts`, не `.js` і не `.txt`. Windows приховує розширення — поверни до дня 1.
3. **Крапка з комою.** Не обов'язкова, але вимагай для однаковості. Дискусію «чи потрібна» не починай.
4. **Хто вже щось знає.** У класі майже завжди є один-два, хто пробував програмувати. Дай їм зіркові завдання одразу, інакше вони нудьгуватимуть і збиватимуть темп.

### Що показати на проекторі перед початком (3 хвилини)

Створи файл, напиши `console.log("Привіт")`, запусти. Покажи весь цикл: зберегти → запустити → побачити результат. Це головна нова механіка дня, і вона має бути показана, а не описана.

## Що піде не так

- **Кодування.** Розібрано вище. Найчастіша проблема дня.
- **`node hello.ts` замість `node app/hello.ts`.** Помилка `Cannot find module`. Вимагай дивитись на шлях у повідомленні помилки — там видно, де Node шукав файл.
- **Стара версія Node.** `Unknown file extension ".ts"` означає, що Node не вміє TypeScript. Резерв — `npx tsx app/hello.ts`.
- **Забули зберегти файл.** Запускають старий код і не розуміють, чому нічого не змінилось. Це та сама помилка, що з `git commit` у дні 2. Скажи: **Ctrl + S перед кожним запуском**.
- **`process.argv` дає не те, що очікують.** Перші два елементи — шлях до Node і шлях до скрипта. Аргументи починаються з третього. Це прописано у файлі учня, але буде питання.
- **`"5" + 3`.** Дає `"53"`, а не `8`. Хтось на це наткнеться. Це чудовий момент, щоб показати, навіщо типи, — але не роби з нього окремої лекції.
